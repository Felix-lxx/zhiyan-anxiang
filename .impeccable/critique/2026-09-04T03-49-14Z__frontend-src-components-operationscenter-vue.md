# 智演安巷：功能完成度与页面改造审查

## 结论

当前是“能运行的主案例原型”，还不能称为“功能完备的演练平台”。三维、道路规划、居民移动和事件记录不是空壳，但配置、任务、仿真、评分、复盘之间仍有关键断点。

本轮重新验证：后端 20 项测试通过，前端构建成功。浏览器只读检查了现有已结束场次，没有修改演练数据，也没有据此宣称运行态已全部验收。

## 1. 现在真正实现了什么

| 模块 | 已有能力 | 距离完整功能的差距 |
|---|---|---|
| 社区与场景 | 地图对象、道路编辑、场景参数、校验发布 | 三维建筑和设施仍是固定布景，未统一读取地图配置 |
| 三维导演台 | 旋转缩放、多视角、对象选择、空间操作入口 | 场景过暗，异常人员不突出；结束后仍保留操作现场布局 |
| 道路与机器人 | 道路图 A*、封锁后重规划、逐段移动、任务排队/取消、到达后广播 | 缺完整巡逻感知—复核—自主决策闭环；起终点接入道路仍可能穿越障碍 |
| 居民仿真 | 连续移动、分流、重点人员速度差异、拥堵减速、累计烟气暴露 | 固定 18 人与固定出生点；护送主要是速度调整，没有实际护送者协同 |
| 决策与任务 | 可配置决策文字、生成任务、记录完成事件 | 触发条件和后果尚不是完整可执行规则；缺超时处理、现场条件与证据校验 |
| 手机协作 | 独立链接、加入码、实时快照、反馈影响仿真 | 身份可自行切换，任务未按责任分配；反馈记录不等于真实在线状态 |
| 平行推演 | 同一历史下计算不同疏散策略的未来结果 | 固定策略预测，不是可独立操作、保存和采用的两个世界；机器人方案也未分别变化 |
| 自适应导演与效果 | 按态势选择扰动，声音、火烟和镜头效果 | 自动触发依赖浏览器定时器；灯光和镜头共用开关 |
| 评分与复盘 | 事件证据、实时评分、结束评分、JSON 导出、后端历史状态重建 | 评分仍偏“做过动作就得分”；页面没有可拖动播放的三维回放 |

因此，不应继续把“感知闭环、完整回放、自由平行推演”标成已全部完成。

## 2. 页面审查

设计有消防演练特征，不是通用后台换皮。现有空间操作、主场景、互斥抽屉和手机大按钮值得保留。主要问题是场景里发生什么、为什么发生、现在该做什么，仍不够清楚。

| 可用性指标 | 分数 /4 | 主要问题 |
|---|---:|---|
| 状态可见 | 3 | 未撤离人员缺直接定位 |
| 现实语言 | 2 | 技术代码、英文状态外露 |
| 控制与自由 | 2 | 结束、删除缺确认或恢复 |
| 一致性 | 3 | 配色统一，数据与阶段呈现不一致 |
| 错误预防 | 1 | 高影响操作防误触不足 |
| 易于发现 | 3 | 多个图标入口需要探索 |
| 操作效率 | 2 | 坐标录入、历史场次切换不便 |
| 审美与简约 | 2 | 三维太暗，功能文字偏小 |
| 错误恢复 | 2 | 加载失败与重试入口不完整 |
| 帮助引导 | 3 | 有指引，缺结果解释 |
| 合计 | 23/40 | 需要明显完善，不是验收通过分 |

认知负担检查有 4/8 项未通过：七个同级功能入口、异常缺少突出显示、对象选择过长、评分与现场需要来回核对。

自动扫描五个 Vue 文件发现 0 项；浏览器检测提示项目页 2 项、导演台 47 项、手机页 4 项。两者覆盖范围不同，数量不能当作缺陷数。小字问题有实际证据；背景色、品牌青绿色等提示包含假阳性。检测只在独立无头浏览器运行，用户当前标签页没有可见覆盖层。

## 3. 五项优先整改

1. **[P1] 统一空间与仿真数据。** 地图里配置的楼栋、起火点、出口、居民，必须成为三维显示和后台计算的同一批对象。否则美化模型后仍然是另一套演示场景。对应设计工作：$impeccable shape。
2. **[P1] 将任务变成真实处置流程。** 必须有责任人、目标、前置条件、执行进度、结果证据、超时后果；手机不能任何身份都完成任意任务。“居民清点”必须对应具体人员，不能一次反馈就解除所有失联。对应：$impeccable shape、$impeccable harden。
3. **[P1] 补齐复盘和分支操作。** 结束后进入复盘态；点击扣分定位事件，拖动时间轴恢复现场，再从选定时刻建立替代方案。区分历史评分版本，避免不同口径混在一起。对应：$impeccable shape、$impeccable clarify。
4. **[P2] 提升现场辨识度。** 保留夜间氛围，但提高道路、人物、重点设施的辨识度；“1 人未撤离”应能点击定位。对小字和状态标签统一调整，而非增加霓虹或装饰卡片。对应：$impeccable colorize、$impeccable typeset。
5. **[P1] 明确操作边界和设备边界。** 结束演练、删除对象增加保护；自动事件导演与纯视觉设置分开。窄屏导演台存在主按钮名称丢失问题，应修复并明确引导手机用户进入参演端。对应：$impeccable harden、$impeccable adapt。

### 用户风险与情绪旅程

- Jordan，新手：右侧七个图标需逐个探索；难理解现场状态与历史评分证据的口径差异。
- Alex，设计员：无法确认地图修改是否进入三维；历史场次切换入口不足。
- Casey，手机参演者：切换身份仍看到同一组任务，居民也看到机器人广播；结束后仍突出旧险情和待办。

体验目前是“进入有现场感—操作时迟疑—结束时缺少结论”，需要把最后两段补完整。

次要问题：抽屉按 Escape 未关闭；部分说明文字只有约 9–10px；任务显示 pending；地图标签局部重叠。当前桌面地图布局已比旧截图改善，不应继续按旧截图判断整页仍然失控。

## 4. 下一步开发什么

下一轮建议只围绕一个完整交付目标：场景驱动的空间处置闭环。不是再新增几个模块入口。

| 顺序 | 开发内容 | 验收方式 |
|---|---|---|
| 1 | 建立场次冻结快照，统一地图、楼栋、出口、起火点、居民组和机器人初始位置 | 配置 60 人后，三维、手机、统计均为 60 人；修改草稿不影响已开始场次 |
| 2 | 三维对象绑定业务 ID；选中道路、居民、机器人后展示对应动作与预计影响 | 封锁指定道路后，服务端、三维路段和实际路径一致；不可达时停止，不能穿楼或瞬移 |
| 3 | 实现任务状态机及可执行决策条件 | 未满足条件不能完成；超时产生后果；完成动作确实改变关联对象，而不只是变成绿色 |
| 4 | 补机器人感知与执行链、角色任务协作 | 机器人连续采样发现异常并复核上报；物业手机完成指定处置，主台立即看到效果和证据 |
| 5 | 将上述过程接入可操作回放和结果评分 | 重放同一时刻得到相同道路、人员和任务状态；错误操作不能仅因“点击过”而得分 |

完成这条闭环之后，再做自由分支推演、进一步模型精细化和更多案例。不能同时铺开更多“半实现”功能。

创新点应落在三个能亲手验证的地方：

- 可解释改道：点一条路线，能看到为何选它、封路后为何换路。
- 真实人机协作：机器人发现的信息触发人的任务，人的处置反过来改变环境。
- 可复现反事实：从同一事件时刻换一个决策，观察并保存不同结果，而不是只换一组统计数字。

## 5. 页面如何调整

| 页面 | 应当怎样展示 |
|---|---|
| 项目入口 | 显示“继续演练、准备场景、查看复盘”，缩减无行动价值的统计卡 |
| 社区编辑 | 中央地图，左侧对象目录，右侧选中对象属性；支持拖动、吸附、连线和二维/三维预览 |
| 场景编排 | 用事件—决策—任务流程展示触发关系，配置旁能直接测试后果 |
| 三维导演台 | 三维占主体；顶部仅状态、时钟、开始/暂停；侧边只展示当前选中对象和异常；点击对象出现相关动作 |
| 手机参演 | 只突出“我的当前任务”：地点、步骤、剩余时间、证据、提交结果；结束后显示个人结果 |
| 复盘/平行推演 | 独立工作态；底部可拖动时间轴，右侧原因与证据，双世界共用时间和镜头 |

模型优先补有业务意义的结构：楼栋入口、楼梯连接、充电棚、电源箱、消防设施、集合点与道路碰撞边界。树木和车辆可以后置。继续统一现有 SVG 图标体系、字号、间距和状态色，最后执行 $impeccable polish。

最终验收应由陌生人完成：配置场景 → 开始 → 封路 → 机器人改道 → 手机完成处置 → 观察人员与环境变化 → 回放证据 → 对比另一决策。还需按原方案验证连续运行三轮、30 终端同步、断线恢复和重复提交。

这些是演练规则模型的验收，不代表真实火场预测或安全决策能力。本轮没有修改业务代码。
