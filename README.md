# 智演安巷——面向老旧小区消防治理的数字孪生与智能决策平台

面向社区组织者与参演人员的消防训练平台，连接场景准备、三维推演、疏散协同、责任任务、集合清点与评分复盘。

## 使用入口

首页支持继续未完成训练、准备新训练与查看上次复盘。完整操作步骤见下方[一次完整训练怎么操作](#一次完整训练怎么操作)。

任务、助手、室内观察与集合清点共享一个操作工作区。同一任务内打开和返回知识原文时保留证据草稿；提交后写入服务端，刷新恢复已保存状态。

## 智能体的实际定位

采用**一个协调器、四类能力**：现场感知、方案规划、资源协同、执行监督。它围绕居民疏散目标读取服务端现场，比较动作，等待人工批准，通过统一命令服务执行，并持续检查真实回执。

- 默认可使用本地目标解析与确定性规划；配置并授权模型后，可用于目标理解和场景解释。
- 申请方案审阅时暂停现场，确认后恢复；按剩余行程选择统一的 30–90 秒预演窗口，等价分流结果合并，厨房可比较“撤空后关门控烟”动作。
- 已批准步骤持久化依赖和命令编号，登记居民、值守员、机器人及房门资源归属；重启接续原命令，人工接管后让出控制。
- 案例责任任务与集合清点纳入监督范围；燃气、电源操作及核验证据由责任人完成。
- 厨房按居住楼层拆分疏散与护送批次，起火层优先，其后为上部和下部楼层；跨出口统一排序。房门、广播、护送行动关联对应责任任务，满足核验条件后可直接进入具体任务。
- 消防车计划停止或让出控制后，已受理行程继续占用实体车辆；其他计划等待实际行程或作业结束，不能凭资源归属释放覆盖在途动作。

四类能力是同一协调器中的模块，不是四个独立大模型。评分、移动、碰撞净距、到位和任务合法性由服务端规则确定。实现及验证见[智能体能力核对](docs/2026-10-23-演练操作修复与智能体能力核对.md)。

## 最新整理 · 2026-11-10

- **训练档案与经验**：结束训练时一起冻结成绩和档案；未完成、低分及手动训练同样保留事实。复盘可下载档案并进入经验审核，发布后才参与后续 RAG 检索。
- **助手对话留存**：问题、回答、引用和快照时刻按场次与账号保存；支持刷新恢复、分页和清空，旧请求不能在清空后重新写回。
- **供水与建模**：汇总独立水源、喷水后逐楼栋放行、绕楼水带、消防车设备和本地 CC0 PBR 材质；保留来源、许可及资源整理脚本。
- **仓库与部署**：纳入快照压缩维护命令、新增表初始化、相关回归和验收文档；本地配置、数据库、缓存和临时输出保持忽略。

历史成绩不按新规则重写；历史档案补建标记为重建来源，不补造原模型版本。单场训练事实与预测—观察对照分别记录，不自动把单次结果转成策略收益。[训练信息回收与经验审核闭环](docs/2026-11-09-训练信息回收与经验审核闭环.md)。

## 任务编排与三维表现

三维近景同步升级：接入本地 CC0 实拍 PBR 材质，补充消防车泵组、水炮与真实接口连接、厨房台面器具及机器人设备细节。水带沿服务端确认路径绕楼并保持离地，厨房与楼栋材质统一响应画质切换，暂停时纹理解码完成会重绘。三维与材质回归 46 项通过，类型检查和生产构建通过。[资源来源与验证范围](docs/2026-11-09-三维材质与消防设备升级.md)。

充电棚压制方案支持逐楼栋放行、广播依赖、每批喷水核对与接续。新场次逐个记录水源状态；支持预览并指定供水水源，主水源失效不再误停备用供水。所用水源失效会停止喷水、定位受影响批次并要求重新比较。车辆工作区可直接切换“到场调度 / 供水与喷水”，16px 正文，沿用单面板布局。预演仍只覆盖首栋及首批可用护送资源；部署必须满足实际车宽、转角、水带长度和射程，详见 [P2 交付与剩余项](docs/2026-11-09-P2-充电棚放行编排.md)。

厨房疏散按楼层组织护送批次，统一展示自动行动、责任任务和集合清点。核验提醒直接定位单项任务，分别显示等待触发、现场处置、可提交核验和超时状态。任务详情沿用原工作区，16px 正文、14px 辅助信息，不增加悬浮窗口。

本轮补齐计划结果一致性：到场后重新规划仍需核验责任任务与集合清点；批次区分已到场、受阻和人工接管；无效楼层请求不会留下方案审阅暂停。供水、车辆、任务依赖和助手等针对性后端回归 **62 项通过**。真实浏览器检查了 1366×650 与 390×844 的导演台、助手和车辆工作区，已检查状态无面板直接重叠，手机文档宽度与视口均为 390px。本轮未重新运行两案例完整评分，也未执行低配设备性能基准。

## 快速启动

### Docker Compose

准备 Docker Compose，在仓库根目录运行：

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
docker compose up --build
```

访问：

- 页面：[http://127.0.0.1:5173](http://127.0.0.1:5173)
- 健康检查：[http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health)
- 接口文档：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

开发引导账号在本地 `.env` 的 `BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_PASSWORD` 中设置。共享部署应配置独立密码、JWT密钥和明确的前端域名。

### 本地开发

环境：Python 3.11+、Node.js 22、npm。以下为 Windows PowerShell 示例，均从仓库根目录开始。

后端：

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
Set-Location backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DATABASE_URL='sqlite+pysqlite:///./zhiyan-local.db'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

另一终端启动前端：

```powershell
Set-Location frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

SQLite 用于单机开发；Docker Compose 使用 PostgreSQL。需要手机参演时，前后端监听地址、CORS 和分享链接应配置为手机可访问的局域网地址。

## 一次完整训练怎么操作

1. 登录管理端，创建示例社区或选择现有社区。
2. 进入场景准备，选择充电棚/厨房，核对火点、人口、通道、任务与资源，校验并发布。
3. 新建场次。默认教学训练；需要考核时，在“更多工具 → 场次与显示”选择下一轮模式后新开一轮。
4. 开始推演，查看巡检或室内烟感确认。打开指挥助手的“目标计划”，设置人员范围、护送与机器人广播。
5. 生成并阅读方案。现场自动暂停；核对预测和前置条件后批准，现场继续。
6. 按任务提示完成断电或燃气、门控、广播及护送核验。无在线处置人员时可使用总控代办，仍需到位回执与证据。
7. 从态势区“待清点”进入名单，逐人核对已到场居民；未到场者定位寻找。
8. 核对任务、清点和指令状态后结束评分。在复盘中查看证据，或从同一历史时刻建立另一决策分支。
9. 结束训练时自动保存训练档案，并为具有冻结空间的场次生成经验草稿，未完成或低分训练也会保留事实。在复盘的“训练档案”中下载记录、完善与审核经验；发布后才供后续训练检索。计划的结果核对仍可单独保存预测与观察对照。

训练档案保存场景与模型修订、冻结成绩、人员到场与清点、逐人暴露、任务核验、结束时的设备状态和关键事件摘要。旧场次可在复盘显式补建，保留原始成绩，并标记原模型修订未确认。单次训练事实不会被直接当作策略收益或自动修改评分规则。

助手问答按场次和当前账号保存，刷新后恢复，支持加载更早对话和明确清空。问题、回答、引用与快照时刻一起保留；清空不删除训练档案、评分和经验资料。模型与语义服务授权在刷新后仍需重新确认。实现、接口与本轮验证见[训练信息回收与经验审核闭环](docs/2026-11-09-训练信息回收与经验审核闭环.md)。

教学模式最低任务预算：电源240秒、燃气300秒、房门420秒、广播360秒、护送600秒；原定时限更长时保留原值。这些是软件训练参数。

## AI 助手配置

“知识与预案”内置 11 份有官方来源链接的资料摘要和 5 份项目说明，支持维护自己的社区预案。场景问答检索适用发布资料，目标计划保存版本化参考依据。默认使用关键词 RAG；语义检索需要单独配置 Embedding 服务并授权，详见[本轮资料清单与验证](docs/2026-11-04-RAG知识扩充与验收修复.md)和[知识库配置](docs/2026-11-02-知识库与场景RAG.md)。

助手的“场景对话”和“目标计划”支持讯飞语音输入：录音结束后转成文字，由用户确认再发送。听写与问答模型分别配置，详见[语音听写接入](docs/语音听写接入.md)。

离线训练不需要模型密钥。使用兼容服务时，在本地 `.env` 设置：

```dotenv
ASSISTANT_PROVIDER=compatible
ASSISTANT_BASE_URL=https://api.deepseek.com
ASSISTANT_MODEL=<你已开通的模型名称>
ASSISTANT_API_KEY=<本地密钥>
ASSISTANT_TIMEOUT_SECONDS=60
```

也支持 Ollama：`ASSISTANT_PROVIDER=ollama`。重启后端，在助手中授权调用。模型名称以实际服务账号可用项为准，密钥不写入前端或提交记录。详细操作见[助手配置说明](docs/场景AI助手_使用与配置.md)。

技术栈：Vue 3、TypeScript、Vite、Three.js、FastAPI、SQLAlchemy、PostgreSQL/SQLite、WebSocket。当前以模块化单体交付，具体事务和实时链路见[架构文档](docs/architecture/README.md)。

关键职责：`scoring.py` 统一冻结世界评分，`scoring_reference.py` 计算效率参考；`exposure.py` 与 `score_evidence.py` 分离暴露累积和结果证据；`knowledge_ranking.py`、`knowledge_ingestion.py` 分别负责排序与新版本切分；`task_guidance.py` 解释权威任务状态。`indoorGeometry.ts` 负责楼内几何与镜头构图，界面不自行重算得分或改写服务端路径。

`training_archive.py` 保存结束事实并关联经验草稿；`assistant_conversations.py` 管理账号隔离、分页与清空代次；`agent_release.py` 和 `water_resources.py` 共用楼栋放行、有效供水及几何约束。PBR 资源及许可位于 `frontend/public/assets/surfaces/`，下载脚本位于 `scripts/fetch-surface-assets.ps1`。

知识、语音与智能体的代码边界及数据流见[架构说明](docs/architecture/README.md#知识语音与规划边界)。知识发布、经验条件比较与模型工具推荐分别处理，推荐不直接执行命令。

## 模型、数据与交付范围

- 三维资产随部署本地提供，来源和许可在资产目录的 `SOURCES.md`、`LICENSE` 中保留；人物为带动作的低多边形资产，机器人为开源网格与项目补充组件。
- 火势、烟气、人员与车辆是规则化训练仿真；尚未接入真实机器人、车辆或现场传感器。
- 室内外移动使用连续图、容量、间距与队列约束，不代表全局刚体碰撞或照片级重建。
- 房门状态、楼梯通道、路径和渲染读取冻结空间数据；模型加载失败时保留轻量替代。
- 长场次和大人口仍需按部署规模做容量验证。传输恢复改进不等于后台负载问题已经全部消除。
- PDF业务报告、BIM/GIS导入、IoT/MQTT和实体设备接入尚未交付；当前复盘可导出结构化JSON。
- 本地配置、数据库、缓存、日志和临时截图不入库。第三方许可文件与可复现的模型制作工具保留。

第三方资源各自遵循随附许可；项目源代码的授权范围以根许可证为准，仓库未提供根许可证时不推断商用授权。
