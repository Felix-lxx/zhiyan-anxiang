# 通行几何与智能体执行升级

## 本轮问题与实现

1. 车辆过去只检查道路宽度和封锁状态，可能沿错误绘制的道路穿楼。现统一使用冻结建筑的矩形轮廓检查完整路段，车身半宽、前后悬伸和转角空间分别参与校验。拒绝不可通行路线并说明原因。
2. 机器人路线增加 0.85 个场景单位的净距，覆盖内置备用模型转向时的对角占地；该值用于场景仿真，不是消防规范参数。
3. 楼门过去直接连接最近路网节点，最近节点在楼后时会穿过住宅。新场次通过可见性图求解门前通道，在楼体外保留必要拐点；增加门厅到正面楼门的连续连接。
4. 建筑原先为实心盒体，门只是贴在外墙的装饰。现在精细和远景 LOD 均为中空外墙、实际门洞及打开的门扇，避免切换画质后门洞重新封闭。
5. 三维插值不再在路线缺失时生成直线。连续改道、后退沿已知折线移动；断线、历史跳转或无法证明连续性的快照直接对齐服务端位置，不伪造中间行程。
6. 室外和集合通道与楼体相交时从寻路排除，恢复道路不能解除几何问题。智能体方案列出具体通道与原因，原方案面板内展开，三维道路详情显示同类提示。
7. 配置预览缺少车辆救援投影，已抽取 `project_rescue_state`，与正式场次、复盘和分支使用同一计算函数。
8. 新建示例地图增加楼西消防转角，消防车不再沿侵入 3 号楼净距范围的原斜线接近。

## 升级后使用

- 刷新网页后，建筑门洞与移动插值更新即可生效。
- 在场景配置保存后创建新演练，使用新的门厅及绕楼通道。已有场次保留冻结空间，不自动替换道路或篡改历史事件。
- 已有社区若仍使用原斜向消防接近道路，需要在地图编辑中调整：可参照新示例的中部路口 `(48,38)` → 楼西消防转角 `(48,54)` → 3 号楼路口 `(58,54)`，并根据自己建筑尺寸复核净距。程序不覆盖用户编辑过的社区。
- 指挥助手 → 目标计划 → 重新比较。若显示“地图通行检查”，展开查看通道名称；有可达替代路线的方案仍可选择，没有可达路线的方案不能执行。
- 旧持久化状态按导航版本检查；升级前尚未批准的方案须重新比较，避免继续执行旧预测。

- 关键后端检查：17 项通过，覆盖几何净距、绕楼连接、车辆调度/救援及智能体执行。

## 自我拷问

**是否只修了外观？** 没有。阻挡检查进入服务端寻路、车辆调度、方案预演与恢复道路命令；模型门洞修复与这些检查配套。

**是否把不能通行的路线偷偷放宽？** 没有。新示例修改了道路拐点；既有地图保留，并明确报告不能通行的原因。

**是否靠瞬移伪造连续运动？** 有有效折线时逐段前进。缺少路径证据时只能对齐权威位置，不声称已恢复遗漏的中间轨迹；这类网络缺口仍可进一步通过轨迹增量协议改善。

**是否已经覆盖全部碰撞？** 目前覆盖楼体轮廓、路段净距与车辆转角的保守检查，不是完整刚体物理引擎。树木、临时杂物、人与人及多车间的精细碰撞仍需独立设计；旧场次错误拓扑也不会自动修复。

**是否为了展示增加重叠面板？** 没有。按 Impeccable 的原界面约束，检查结果使用已有助手正文中的原生展开区、正常文档流和限高长列表。
