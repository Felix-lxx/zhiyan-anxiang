# 智能体执行效果核对

## 本轮交付

补齐“比较方案—人工批准—执行—观察结果—回看现场”的结果核对环节。沿用现有连续空间仿真和复盘接口，不改变人员碰撞、通道容量、护送会合或机器人到位条件。

入口：演练导演台 → 指挥助手 → 目标计划。批准方案后，在“执行”中点击结果核对入口，或直接打开“依据”。

1. 批准时保存本版方案的居民范围、预测到场人数、暴露人数、累计排队、预测起点及事件序号。
2. 服务端在原定观察时刻核对同一批居民。暂停不消耗演练时间，关闭助手不影响核对。
3. 展示预测、实际和差值；批准至执行存在的时间差单独说明。
4. 保留观察期间的外部改派、道路和环境变化等事件引用。变化列表可定位历史时刻。
5. “回看三维现场”关闭助手，进入已有复盘工作区，以对应时间的实际居民、机器人和环境状态展示结果。

## 数据与运行设计

新增 `agent_decision_checks`，以 `run_id + revision` 唯一约束绑定批准版本。`basis` 保存冻结口径；`result` 保存核对结果。既有数据库启动时通过现有表结构初始化创建新表，不修改已有场次数据。

调度器除执行中和待清点的计划外，也扫描有待核对记录的计划。因此停止后续自动下令、提前完成或让出控制，不会丢失已批准决策的结果观察。

核对只在达到目标时间或场次提前结束时运行。计算使用现有 `simulation_state`，事件过滤到观察时刻；调度器晚到时不使用更晚的现场冒充原预测时刻。核对以条件更新认领，在同一事务内持久保存结果和计划事件，失败回滚后可重试。已完成记录不再计算。

查询接口只读取持久结果；更新计划时间戳后，由既有私有智能体实时通道推送。分页范围保持有界，界面提供最近五个批准版本切换。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 到达集合点 | 冻结目标居民中，实际状态为 `evacuated` 的人数 |
| 暴露超阈值 | 冻结目标居民中，累计 `smoke_exposure > 5` 的人数，与预演原口径一致 |
| 累计排队 | 同批居民 `queue_seconds` 总和，单位人秒，按原预演方式取整 |
| 差值 | 实际值减预测值；该数值不用于自动加减评分 |

场次提前结束、居民数据缺失或确认时预测窗口已经结束时，不计算完整窗口差值。迟于预演起点但仍在窗口内批准时，展示确认延迟，并保持原定观察时刻。

人工改派和外部事件可能改变结果，因此该比较是决策预测校验，不是对智能体的因果效果估计。事件列表展示前八条及总数，完整记录仍在复盘中。

## 展示与排版

- 沿用原助手内部滚动区域，不增加绝对定位面板。
- “执行”提供直接入口，“依据”容纳版本选择、指标表和可折叠事件列表。
- 正文 16px、辅助说明 14px、交互目标至少 44px；指标表固定宽度，窄屏文字换行，事件操作另起一行。
- 跳转复盘前关闭助手，避免两个交互层同时遮挡三维现场。

## 自我拷问

**是否用当前状态冒充预测时刻结果？**  
没有；以原观察秒数重建状态，过滤未来事件；测试核对其与正式复盘接口的结果一致。

**停止智能体就不再检验原方案了吗？**  
仍核对。执行控制与结果观察分别管理，人工接管的事件也会保留。

**重新规划会把原预测覆盖掉吗？**  
不同批准版本独立存储，各版居民范围来自当时实际分配名单。

**是否误把居民到场当作已清点或救援完成？**  
核对只报告上述三个已有预演指标，不改变任务完成、护送或人工清点规则。

**是否又增加一个难找、遮挡现场的模块？**  
执行页直接跳转依据页，结果表和事件列表沿用原面板文档流；回看操作切换到既有复盘页。

## 验证范围

本轮完成 3 项相关后端检查、前端类型与生产构建；1440×900、1366×650、1024×800、390×844 四种视口的助手流程和结果表检查通过，未发现新增横向溢出，回看操作会关闭助手。人工查看短屏和手机截图，Impeccable 布局扫描无发现。本地服务重启后数据库和健康检查正常。

核对记录从本次升级后新批准的方案开始生成；历史方案缺少冻结的预测人口及事件起点，不回填推测结果。本轮未进行全系统或大规模容量验收。
