# 实时联动升级与验收

本轮目标：把确认操作、服务端执行、三维表现、手机同步与评分证据连接起来，优先解决“点了不知道是否执行”“旧画面覆盖新操作”“低分但不清楚原因”。沿用现有页面与训练模型，不另加仪表盘。

## 已交付

### 1. 统一指令与事务

新增 `POST /api/v1/drills/{id}/commands`，复用既有领域校验，支持演练状态、事件注入、道路恢复、居民分流、机器人操作、搜索指派、导演任务操作、参演反馈与事件导演配置。

- 指令带唯一编号；同编号同内容返回当前结果，不重复产生处置效果；同编号不同内容拒绝。
- 业务事件与指令回执在同一事务提交。回执保存失败时，已经写入事务但尚未提交的业务变化也回滚。
- 网络不确定结果只自动重试一次且复用编号；仍未确认时提示核对回执，不谎称操作失败或成功。
- 支持可选的预期事件序号，过期请求返回冲突。道路、居民和机器人空间预演均返回事件序号，确认操作统一携带该序号；现场变化时旧预览不会执行，并自动生成最新预览。
- 不新增数据库表。指令与证据存于原事件记录；旧接口保持兼容。手机端既有任务接口仍保留原身份、证据与重复提交校验，未全部迁入导演指令入口。

### 2. 一致的实时现场

新增 WebSocket 协议版本 2。首次连接发送完整快照，后续递送带基础版本的差异；稳定状态发送心跳。连接断开、版本缺口或心跳失效后重连并取得完整快照。

- 版本由事件序号与模拟秒数组成；前端拒绝晚到的旧 HTTP/实时响应覆盖当前画面。
- 数据传输基线与界面上的 HTTP 结果分开维护，避免两条链路互相破坏。
- 服务端同一场次、同一版本的完整计算结果在进程内共享；读取与指令使用一致的进程锁次序。
- 新协议订阅者不推进模拟，推进由原有后台引擎负责；协议 1 为兼容仍保留原有行为。
- 差异更新保留未变化的静态世界对象引用，避免无关的静态模型重建。居民等数组仍整体替换，不是逐实体二进制协议。

检测周期为 250 毫秒，心跳为 5 秒；这是调度配置，不是网络端到端延迟承诺。本轮没有完成压力下的延迟基准。

### 3. 看得懂的执行进度

导演台底部增加执行进度入口，复用「处置任务」抽屉，不增加常驻悬浮卡片。展示最近 24 条指令，默认展开 4 条。

- 居民按实际仿真状态判断是否到集合点，不以接口成功作为撤离完成。
- 机器人移动回执关联真实任务队列，区分等待、执行、受阻、取消与到达。
- 暂停和结束时明确说明未完成状态；搜索员前往会合期间显示正在寻找。
- 展示人员行为、到达人数、行程估计、关联事件，支持定位人员与回看决定。
- 同区展示当前总分与尚未满足的评分项依据。评分继续使用既有规则，不人为抬高分数；耗时估计不包含未来排队或新扰动。
- 时间轴不重复展示指令回执与其业务事件，但回执及关联记录仍完整保存。

### 4. 空间操作与首页

- 首页「效果图／三维预览／平面图」明确分离；实际预览懒加载三维组件，读取所选场景配置，支持拖动旋转及滚轮缩放，失败时提示检查配置。
- 居民跟随面板新增「指挥此居民」，切回总控并进入该居民的路线选择；确认后写入服务端。
- 从居民选择切换到道路对象时恢复观察工具与总控视角，显示道路操作。
- 删除覆盖布局的旧强制定位，居民操作面板不再被底部时间轴挡住。
- 新执行反馈使用现有设计令牌，检查桌面与窄屏；窄屏长状态文案截断，抽屉可滚动。

纠正一项判断：原 `interactive=false` 只是禁止处置操作，并没有禁用 OrbitControls；不能把预览已有的旋转缩放算成本轮新增功能。

## 亲手验收

1. 更新代码后重启后端，刷新前端；进入首页，切换「三维预览」，转动模型，确认不是效果图。
2. 进入新的演练场次，点击「开始推演」。
3. 打开「指挥」，通过对象选择器选择居民，点击「指挥此居民」。
4. 选择北门分流，查看预览并确认。底部打开执行进度，核对当前行为、到达人数；等待实际撤离完成，不把“已提交”当成“已到达”。
5. 选择北门道路，注入通道堵塞。观察封锁状态和受影响路线；手机参演端应同步出现事件。
6. 暂停与继续，核对回执和人物状态；机器人移动任务可用相同入口检查队列。
7. 手机断线后重新联网，无需重新登记；连接恢复后取得当前现场。
8. 在执行进度点击「回看决定」，对照关联事件、现场与当前评分依据。

## 自我拷问与未完成边界

- 是否只多了按钮？不是。浏览器实际下发居民和封路操作；接口测试进一步验证真实到达、任务状态、双端同版本及回滚。
- 是否误把提交当完成？移动类指令根据真实仿真状态生成回执。广播、设置等即时动作仍表示该动作已生效，不等于整项救援任务完成。
- 是否证明全系统高并发可用？没有。本轮仍是单进程引擎与进程缓存；多实例需统一推进租约、数据库幂等约束或集中命令队列、跨实例消息分发及压测。不可直接用多 worker 宣称可扩容。
- 是否具备生产账户与权限交付？仍保留原开发账号体系；正式双角色账号管理、授权收敛、安全与运维验收须单独完成。
- 是否成为真实火灾模型？没有。居民、烟气、道路与会合仍是现有规则训练模型，不是 CFD、实测 BIM 或真实机器人控制。
- 是否所有动作都有新回执？本轮覆盖导演主操作。旧接口、旧场次历史操作与手机任务流程不追补成新指令；既有事件证据仍可复盘。
- 下一步优先什么？先把空间预览版本校验、重复指派的部分覆盖语义、长期运行与多手机负载验收补齐，再推进正式双角色权限。不要继续堆新仪表盘。
