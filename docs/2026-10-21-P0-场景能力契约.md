# P0：场景能力契约与准备入口

日期：2026-10-21
对应规划：P0 稳定基线与契约。

## 已交付内容

新增 `backend/app/services/scenario_contracts.py`，以冻结的数据结构维护案例代码、契约版本、可用状态、允许火源类型、空间种类、参数协议、环境模型及已实现功能。数据库模板名称与自由填写的默认参数不会自动获得运行能力。

- 充电棚：`available`，允许创建、配置、预览、发布和运行。
- 厨房：`planned`，显示建设中，待室内选点、分区环境及任务闭环实现后再开放。
- 未注册代码：`unsupported`，无运行权限。

通过类型化响应向模板与场景接口返回同一能力声明。创建与参数服务检查可用状态；准备校验、预览、发布和新场次检查相同案例能力。预览复用准备校验，不再单独维护另一套起火对象校验。

旧厨房配置不会因为提交充电棚参数而切换案例；不支持的模板在参数校验前返回案例原因，避免提示用户去补充充电棚。

新草稿将旧模板的 `time`、`wind` 翻译为 `start_time`、`wind_direction`；显式填写的新字段优先。已有模板默认数据、场景版本和冻结事件不进行批量改写。这里仅统一现有背景时间字段，按秒指定起火时刻在后续阶段实施。

新场次冻结世界新增 `scenario_contract`，记录当时实际使用的能力和规则标识。历史场次读取原冻结世界，不因当前模板可用性发生变化而失去回放能力。

## 页面入口

场景准备 → 新建场景 → 选择演练案例 → 输入名称 → 创建草稿。

- 案例选择使用原生单选控件及文字说明，可运行状态与建设状态清楚区分。
- 已有场景可以直接新建另一草稿，并可返回原场景。
- 厨房旧配置显示原因、选择可演练案例和历史演练入口；不会加载充电棚预览。
- 新建或切换时取消旧预览并清除定时请求，防止旧响应和旧错误覆盖当前页面。
- 新界面沿用 Impeccable 和现有设计体系，正文 16px、辅助 14px，采用文档流与内部滚动。

## 验证

11 项后端相关检查通过：场景版本、准备/发布、主案例运行，以及新增的能力契约、草稿字段统一、未开放模板无副作用、旧配置不能绕过能力检查、冻结历史回放。

前端类型与生产构建通过。浏览器隔离夹具验证实际生产组件的创建、新建、未开放案例与旧配置显示；1440×900、1366×650、390×844 下无横向溢出或脚本错误。布局规则扫描无发现。夹具用模拟 API 验证页面，真实后端规则由上述接口测试覆盖。

首次浏览器地址指向另一个项目，随后使用本项目独立预览端口完成核对，没有停止或替换其他项目服务。

## 自我拷问

1. **是否只禁用页面按钮？** 后端创建、保存、预览、发布和新建场次均检查能力；直接请求也会被阻止。
2. **是否把已有厨房历史删掉或改成充电棚？** 未修改已有数据。测试确认即使模板身份变化，原冻结世界仍可回放。
3. **是否在每个入口复制一套模板判断？** 可用状态来自统一契约；预览/发布/新场次复用相同配置校验。
4. **增加契约是否等于厨房已完成？** 厨房状态保持建设中，本阶段没有实现房间火源、分区烟气和厨房任务。
5. **是否为了通过检查改变疏散与评分规则？** 本阶段仅新增能力校验、元数据和准备入口；原主案例接口闭环检查通过。
