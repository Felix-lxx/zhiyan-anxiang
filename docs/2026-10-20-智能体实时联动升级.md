# 智能体实时联动升级

## 使用变化

“三维演练 → 指挥助手 → 目标计划”显示“与三维现场实时联动”时，当前协同、排队风险、机器人回执和计划阶段通过现有导演连接持续更新，面板停止定时HTTP读取。关闭助手再打开时使用已接收的最新计划。

连接中断后保留最近状态并提示恢复中，回退定时读取；重新连接后先恢复完整计划快照。历史回放中不执行或刷新实时目标计划。已接受的命令由后台继续推进，不受面板开关影响。

预演超过45秒或相关路况、目标人员状态变化时，方案区域直接说明原因，确认按钮禁用，并提供重新比较入口。重新比较产生新修订，仍需用户批准。

## 实现边界

- `agent_realtime.AgentProjection`：按连接、操作者和最新计划投影。缓存键同时包含场次版本和计划更新时间，因此暂停演练时也能推送批准、停止、修订等独立变化。
- `agent.snapshot` / `agent.delta`：复用现有WebSocket连接与实体补丁机制，但使用独立基准版本；不改变演练事件序号或写入仿真快照。稳定的候选路线和作用范围无需每次重传。
- 管理端显式使用`agent=1`订阅；手机邀请连接即使提供同名参数，也不会获取计划。计划查询仍按账号隔离。
- `connectLive`：分别维护场次与计划基准。任一补丁不连续即重新连接，恢复两份完整快照；计划流不会推进演练事件追赶游标。
- `AgentPlanWorkspace`：对比计划修订、更新时间和现场时刻，防止延迟帧覆盖HTTP确认。新建目标后，旧空帧不能擦除已确认结果。
- 第一视角镜头使用模型沿实际路线运动时的朝向，避免在走廊转角按下一快照方向斜看。位置和通行规则沿用服务端权威数据。

## 自我拷问与证据

1. 是否只把轮询改名为实时？健康流下不再发送周期性计划GET；浏览器脚本覆盖这一行为。
2. 是否会在暂停时漏掉计划修改？后端回归验证冻结场次版本下仍收到独立计划增量，重连后恢复同一目标。
3. 是否把管理计划发送给居民？参演邀请连接订阅检查已覆盖，只有场次快照和心跳，没有计划消息。
4. 是否允许过期方案继续执行？展示层使用只读审批条件投影，服务端批准接口继续执行原有二次校验。
5. 是否通过新增浮窗解决展示？沿用原助手与单一滚动容器；同步提示使用普通文档流，四种尺寸继续核查无横向溢出和标题重叠。

本轮未引入独立消息中间件、额外智能体进程或新的三维位置预测。推送读取不会驱动仿真，也不代替人工审批。
