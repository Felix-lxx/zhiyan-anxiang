# 路由、统一接口与三维社区更新验收

日期：2026-09-06。范围：接续领域类型／API／路由阶段，改善三维模型与入口页面，并复核从配置到评分导出的主流程。不是对所有历史功能的无条件完工声明。

## 一、本轮代码交付

| 内容 | 实际实现 |
| --- | --- |
| 领域类型 | 社区、版本、场景、地图对象、道路、任务、场次、居民与机器人类型进入 `frontend/src/domain`，不再从业务 Vue 文件导入 Community 类型 |
| 统一 API | `api/client.ts` 成为唯一原生 fetch 入口；统一动态令牌、JSON、错误 detail、取消、超时和 401 处理；公开手机接口不携带管理员令牌，不因加入码失效退出管理员登录 |
| 页面路由 | Vue Router history + 页面懒加载；地图／场景／导演台独立地址；场景和步骤、场次写入 query；旧手机 hash 链接兼容迁移 |
| 草稿保护 | 离开未保存配置时取消或放弃；参数页与预览页保留草稿；刷新恢复已保存版本，未保存值不会被伪称为已持久化 |
| 失败反馈 | 登录／社区加载显示失败和重试；旧预览仍显示时明确标注过期，非法参数中止旧请求，避免旧响应覆盖最新输入 |
| 建筑与道路 | 按冻结地图尺寸生成住宅立面、窗台、空调、楼层线、雨棚、屋顶附属结构；近远 LOD 均保留窗户；路面、路缘和标线与风险层分离 |
| 外部模型 | 本地加载小汽车、消防车、救护车以及既有树木、花池；按统一尺寸和地面轴心放置，避开已有楼栋和道路走廊 |
| 页面 | 首页与登录文案落到具体操作；首页使用真实渲染截图；导演台减少浓雾和全路面发光，工具弱化装饰；手机空间工具补足读屏名称与选中状态 |

建筑窗户与部分附属构件使用实例化。模型、Three.js 引擎、控制器和加载器分包，但三维引擎原始包仍约 578 KB，不将本轮描述成高性能实景引擎已完成。

## 三、操作验证记录

浏览器环境：本机 Edge headless，桌面 1440×960、手机模拟 390×844。使用独立命名的验收场景和场次，不清空已有社区／历史场次。

1. 登录进入首页；从地图到场景页，刷新和浏览器前进后退正确恢复。
2. 创建独立场景，修改为 6 人、09:00、水源可用；服务端试算返回 6 人。参数与空间预览互切保留草稿；离开弹窗选择取消保持当前页面。
3. 保存、刷新恢复、运行校验、发布场景、创建场次；刷新仍指向同一场次。
4. 开始演练，选择充电棚，预览机器人路径，确认后服务端真实任务队列非空。
5. 选择居民，下达北侧撤离指令；服务端产生 `resident.command`。道路封锁经过预览与确认，产生 `inject.channel_blocked`。
6. 独立手机上下文无管理员登录，加入为“验收物业一组”；实际提交确认警报，返回 `participant.acknowledge`，请求无管理员 Authorization。导演台无需刷新即可在事件列表看到回执。手机刷新保留登记身份。
7. 双世界策略对比打开两份三维现场；结束演练，确认服务端 ended 与评分存在；导出 JSON 证据报告，从头回放后可回到最终结果。
8. 手机导演台无横向溢出；无效登录令牌触发登录页并保留回跳地址。

初次验证覆盖创建、保存和发布。后续回归复用已发布验收场景并新建独立场次，没有重复将“复用发布场景”计作一次重新发布。

最终浏览器回归记录：`.tmp/workflow-results.json`；已验证场次 `8ab497e0-fd49-450b-bc0d-a14824fceff3`，现已结束。截图及导出报告保留在 `.tmp/workflow-*`，不含登录令牌；验证脚本用测试身份，不在日志输出密钥。

自动化结果：前端 API 单元测试 **4/4**；生产类型检查与构建通过；后端全量测试 **56/56**。浏览器回归无 pageerror、无模型资源失败。构建不是用户行为证据，因此另行保留上述实际请求／事件验证。

## 四、自我拷问与边界

- 是否只是换图片？不是。地图维度驱动的程序模型和本地 GLB 实际进入三维场景；首页仅使用其截图。
- “完整流程”是否代表所有算法全部验证？不是。本轮浏览器验证上述主流程；连续排队、护送会合、空间清点、分支隔离等由后端回归覆盖。未以截图证明全体居民完整撤离，也未新增实测消防模型。
- 对比是否包含真实可编辑分支的本轮浏览器验证？本轮浏览器验证两种策略的持续对比；历史快照可编辑分支属于既有能力，本轮未另行手工重走其全部路径。
- 手机是否真机验收？不是。是手机尺寸和独立上下文测试，真实软键盘、弱网与低配设备帧率还需真机验证。
- 装饰车辆是否参与救援？不参与，点选说明已写清；机器人派遣才会改变任务状态与证据。
- 这是实景数字孪生吗？当前仍是参数化示意社区与规则训练模型，缺少测绘／BIM、真实户型和人流标定，不用于现实疏散安全认证。
- 视觉如何审查？按 Impeccable 对桌面和手机集中检查并修正；Grill Me 的用途是访谈提取，未伪造用户访谈或独立审查结论。本节是代码与测试依据的自我审查。

## 五、下一步建议

下一轮优先选一栋真实社区建筑，接入有授权的户型／BIM及出入口资料，建立模型导入校验、比例校准和道路吸附预览。这样精细模型与疏散空间一致，价值高于继续加入纯装饰资产。随后在实际手机和低配笔记本测量帧率、内存与首屏加载时间，再决定纹理压缩与分级加载预算。
