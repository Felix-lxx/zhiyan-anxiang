# 场景、仿真与三维表现

## 两个案例

| 案例 | 空间与火点 | 关键联动 |
| --- | --- | --- |
| 充电棚 | 选择合法充电棚对象并冻结道路接入点 | 断电、路段风险、消防车供水压制、分流、广播和重点护送 |
| 厨房 | 建筑—楼层—房间地址及米制高程 | 房间—走廊—楼梯—门厅烟气连接、燃气与门状态、楼内连续疏散 |

准备、保存、预览、发布及新场次共用案例契约与校验；失效火点不会静默回退。新场次冻结对象身份、参数、任务、人口、通道和规则版本，历史及分支读取冻结输入。教学与考核时限分别保存，不迁移旧世界。

## 连续运动与模型

人物沿房间、门洞、走廊、楼梯、楼门、室外道路至集合点连续移动，处理容量、间距、排队、会合和差异速度。三维插值沿服务端确认路径与轨迹；门动画、家具、通道净距读取同一空间数据。到场后才可清点，护送先会合后同行。

画质、鸟瞰/跟随/居民视角、楼层剖面和设备定位共用同一实体身份。细节模型失败时保留轻量形体并可重试；销毁释放 GPU 资源并忽略迟到加载结果。资产和贴图来源见各目录的 `SOURCES.md` 与 `LICENSE`，不得清除第三方许可或离线运行文件。

楼栋放行状态牌只读取匹配场次版本的已批准计划；历史回放不混入当前任务状态。入口标记和屋顶标牌仅用于提示，不改变碰撞、路径或评分。具体实现见 [空间呈现记录](../reports/2026-11-10-building-release.md)。

## 供水与放行

新场次逐个记录独立水源。消防车部署须满足道路宽度、转角、停靠、射程及绕障水带长度；到场和有效供水后才开始喷水。水柱与水带连接实际接口，显示层沿确认的绕楼路线绘制，不用直线穿过楼体。

逐栋方案确认喷水后放行首栋，后栋广播和居民释放等待前栋实际到场并重新核对压制。机器人可在上一栋广播完成后提前前往下一栋，但不能提前广播或释放未到批次。指定水源失效会影响后续放行并要求复核，不凭另一个水源的可用状态掩盖故障。

## 评分与预演

社区夜班模式另将通知覆盖、住户回执和实际行动分开。供水故障只改变可用资源，资源就绪本身不抑制火势；有效喷水及对应能源处置才改变训练环境。到户核查与护送共用通行规则和有限岗位；新世界在户门到位后允许敲门回执。未启用该模式的世界保持旧规则，详见[社区训练](community-training.md)。

评分由事件、任务核验及权威人员状态计算；只有全员具备真实到场时刻才形成完成时间。部分疏散和完整疏散使用同一速度延迟扣分；暴露证据区分越阈发生时刻与关联命令时刻。

候选预演是有限时域正式仿真，分批时序估算另行显示，不能据首栋结果宣称全场最优。最新真实成绩及代价见 [验收记录](../reports/2026-11-10-acceptance.md)。全局刚体碰撞、照片级扫描建模和全部人口容量并非已验收能力。
