# 社区夜班：分户通知与有限人手

## 开启方式

场景准备 → 人员与出口 → 社区夜班训练，选择“夜班画像 · 分户通知与有限人手”。设置值守岗位（1–8）和场景种子后保存、发布，再创建新场次。相同空间、人数和种子生成相同画像；数据按匿名训练户组织，不是居民实测档案。

旧场次继续读取原冻结世界。新场次独立冻结环境、居民、编排、空间与评分标识：是否启用夜班画像只控制居民与责任协同，不再决定环境因果模型。普通与夜班新场次均采用因果环境 v2；没有模型清单的历史世界保留原规则。

## 实际操作

新厨房场次可在“楼内烟气与门控 → 按户组织行动”选择户号。这里同时显示厨房门、入户门、玄关烟气、待到场人员及通知状态；“核实本户通知”进入对应住户，随后“返回楼内现场”恢复原门或房间。双门属于不同通道，关闭厨房门不会自动关闭入户门。

1. 在导演台“当前任务”打开“通知到户，责任到人”。按楼栋、楼层或画像筛选；选中住户进入详情，返回保留列表筛选和页码。
2. 电话或入口广播先记录已发出通知，再由参演人员填写收到回执。需要到户时点击“派出值守员到户”，值守员沿服务端通行图前往户门。新世界须实际到门后才能提交敲门回执；到门不自动确认收到。广播覆盖不等于确认收到；需要直接联系的住户不能仅凭广播确认。
3. 收到回执只核实通知。总控可以先比较、批准包含未确认住户的计划：已满足条件的部分执行，未确认部分显示“核实通知”步骤；点击直接打开该户，完成回执后“返回目标计划”。后台复核通知、依赖、通道与岗位，再下达原计划中的行动，不必重新比较。没有已批准计划时，确认本身不下达移动命令。熟睡准备时间、行动速度与护送会合影响后续执行。
4. 岗位页显示正在承担的责任任务和护送对象。接收物业任务占用一个有限岗位；已有任务、实体护送及活动计划归属均影响再次接收。任务核验完成或撤回接收后释放岗位。
5. 手机参演登记后，在“现场回执”使用同一分户界面。提交会写入服务端事件，导演台通过实时通道更新；页面不预填成功状态。
6. 结束归档保存通知进度、回执、未确认户数和模拟条件。历史回放按当时时刻恢复，不能读取未来通知。

到户核查和护送、物业任务竞争同一岗位。无法继续时可查看阻塞原因或改用电话；无回应可填写原因后结束本次核查，住户仍保持未确认。途中撤回先走完当前路段，保留位置后释放岗位，不瞬移到起点。核查人员到门、接收通知回执、安排居民行动是三个不同阶段。

电话、敲门结果仍由参演人员报告。系统只能确认仿真中的路径与到门状态，不以人物动画替代现场核验。

## 仿真与三维

新模式中，水源可用性与火势自然增长分开；“资源就绪”不直接压低火势。实际有效喷水才产生压制；断电、断气分别作用于对应场景，断电不等于电池火情解除。所有系数仍为明确标识的训练规则。

人物速度、路径估计和评分参考共用画像速度。现场详情显示训练户、画像与通知状态；原有脚下轮廓增加待通知、待确认的状态反馈，危险与拥堵颜色优先。定位复用服务端人物位置，并打开对应楼层的第三人称观察；第一视角仍需单独选择，没有增加占用通道的装饰几何。

## 通道条件放行

场景准备的社区夜班区域可选两种分批方式。保存、发布后，新场次冻结该选择；它用于充电棚“压制后分批撤离”方案，不改变手动指挥或立即撤离的含义。

- **按实时通道条件放行**：前批指令实际受理后，逐项核对广播等前置动作、已确认住户、有效压制、车辆独占路段、路线占用与接应岗位。低负载且条件满足时可以并行撤离，不等前批到集合点。占用达到本场冻结门槛（默认 55%）或车辆管制时等待并再次检查；封路、几何冲突或有效压制失效时要求复核。
- **等待前栋全员到场**：保持原有串行顺序，每批仍核对有效喷水。

助手“楼栋放行进展”显示检查时刻、具体等待原因、到场进度及定位入口。默认展开第一批待处理检查，其他批次按需展开；点击关联通道会关闭助手，切换同一个三维现场并高亮服务端确认路段。室内通道按其楼栋、楼层和真实端点高度定位，高亮不改变碰撞或通行。

广播可以用于发出通知，不要求广播前已经取得住户回执；人员放行仍需要确认收到通知。契约 v4 支持批准带通知等待节点的计划，不会自动填写收到回执。未确认的护送步骤暂不预占岗位，值守员仍可执行到户核查；取得回执后再次检查岗位。旧世界及已批准旧计划保留原批准约束。责任任务和活动计划归属沿用现有互斥规则，命令受理时再次检查。

## 归档与经验适用性

契约 v5 的住户记录包含单元、户号、厨房分区、玄关、入户门及门外通行节点；成员与房间、任务、回执和档案共用同一身份。到户核查停在公共走廊，关入户门会检查厨房和玄关内尚未撤离的居民与护送员；关闭后烟气与人员路径一起更新。空间过小、无法容纳独立玄关的建筑保留原紧凑布局，不添加虚构入口。

归档先汇总到场、清点、任务、住户未确认和到户核查未结束事项，再生成完整性标签与经验草稿。已存在的档案保持原哈希与内容；本轮不回写历史档案，也未新增历史更正接口。

新经验保存独立模型清单、当班人数、画像、种子与放行方式，检索时与当前冻结现场逐项核对。模型或条件不同会显示差异；旧经验缺少模型清单时显示待核对，不自动视为适用。本轮实现及实际页面证据见[通知条件编排记录](../reports/current-release.md)。

候选的有界仿真仍主要覆盖首批。实时条件方案不提供虚构的全批完成时间或“无超时”保证；页面明确显示未完成全批动态推演。55% 是既有模型的训练门槛，不是实测消防安全标准。

## 工程与兼容

- `community_training` 冻结在创建事件的世界中；投影从事件重建，无浏览器私有成功状态。
- 社区参数为 `community_profile`、`duty_staff_count`、`simulation_seed`、`building_release_mode`。最后一项为 `shared_corridor` 或 `assembly_serial`，仅在新冻结的夜班世界中生效；未启用夜班模式仍沿用原规则。
- `20261113_task_kind` 为 `decision_tasks` 添加可空 `kind`。新标准任务保存明确类型；保存可编辑旧任务或复制新草稿时固定原语义。历史记录仍支持旧标题适配，冻结事件不改写。
- 引擎检查点修订为15，冻结世界哈希隔离不同空间；新社区契约v5、室内几何v3、厨具v3及住户入口v1。版本v1/v2/v3/v4保留各自冻结规则，已批准旧计划不重编排。
- 到户核查不进入起火房间，目标为冻结户门外的通行节点。烟气停靠阈值随社区世界冻结，属于训练规则，尚未经过实测标定。
- 新增行为复用 `participant.feedback` 和 `task.action` 入口、身份验证、命令及事件体系。

当前功能、界面与发布证据见[当前交付记录](../reports/current-release.md)。
