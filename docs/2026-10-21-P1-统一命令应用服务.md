# P1：统一命令应用服务与执行回执

日期：2026-10-21
范围：统一命令事务入口，完成居民/机器人核心执行规则迁移，增强批准范围校验和来源追踪。

## 交付结构

| 文件 | 职责 |
| --- | --- |
| `app/application/drill_commands.py` | 幂等、计划批准范围、事件/记录/快照原子提交、预期失败持久化 |
| `app/services/movement_commands.py` | 居民分流/护送、机器人移动/取消/重新规划/到位广播规则 |
| `app/domain/errors.py` | 可由 HTTP 或后台调用者处理的领域拒绝 |
| `app/bootstrap/commands.py` | 将应用端口绑定到共享规则及既有读模型、其他领域处理器 |
| `app/services/command_lock.py` | 共享重入锁；保留原进程内完整事务串行化 |
| `ExecutionFeedback.vue` | 真实状态、人工/智能体来源与关联回执就地查看 |

`operations.execute_live_command` 保留为 HTTP 映射。原居民、机器人接口保留为兼容适配器；业务规则已迁移，不再复制两份。智能体执行直接调用应用服务，支持正常回执、预期拒绝和自动让权。

应用服务和移动规则不导入 API 路由或 FastAPI。装配层暂时使用既有 `operations` 中的快照、空间预演、机器人路径/队列辅助和其他领域处理器。这是后续逐条迁移的显式边界，并未宣称所有历史路由逻辑已完全抽空。

## 执行语义

1. 校验当前账号对场次的访问权，并锁定场次命令顺序。
2. 对已有命令记录和历史接受事件做幂等核对；同一编号、不同参数或操作者拒绝复用。
3. 智能体新指令核对当前活动计划、批准版本、步骤、命令编号和参数，不接受超出原批准范围的动作。
4. 核对预演事件序号与必需目标，创建命令台账。
5. 领域规则计算通行、护送资源、机器人队列及真实到位条件。
6. 领域事件、接受回执、状态台账和快照在同一事务提交。
7. 参数或现场规则拒绝时先回滚领域副作用，再持久化失败事件；未知异常整体回滚，交由调用者恢复。

已受理命令的幂等重试读取原回执，不重新执行或改写原始来源。停止、恢复或修订后重新使用原受理动作时，也保留当时的批准版本。

## 来源与展示

新增接受/失败事件记录服务端赋予的 `origin`：人工来源，或智能体计划 ID、批准版本和步骤 ID。客户端没有指定该来源的命令字段，不能通过请求参数伪造智能体授权。

现有增量状态继续携带执行回执，`command_feedback` 投影包含来源。处置任务内原有执行面板显示“人工下令”或“智能体计划 · 批准版本”，可展开指令、计划和步骤编号。历史事件没有来源时不推断补填。失败事件保留来源，旧台账结构不新增数据库列。

三维继续消费同一服务端状态：居民按通道、容量和护送会合推进；机器人按实际路线、队列和到位状态执行。本轮没有新增模型资产、厨房环境或自由火点入口。

## 验证与自审

迁移后的 19 项针对性检查通过，覆盖 HTTP/应用服务共享幂等回执、未批准智能体指令无副作用、后台不调用 HTTP 下令函数、失败事务回滚、实时追赶、机器人队列以及护送接续。前端生产构建通过。

浏览器使用生产执行面板和隔离场景核对人工/智能体来源、受阻/排队状态、旧回执与长编号换行。1440×900、1366×650、390×844 下未发现新增横向溢出或脚本错误；回执在原任务抽屉内展开。

迁移共享锁时发现，延迟类型注解会在错误模块上下文中解析，导致路由参数被误判。锁装饰器显式保留原函数已解析签名，相关 HTTP 与后台调用检查通过。

自审重点：

- **是否只换了函数名？** 命令事务和居民/机器人执行规则均已迁移；后台对原 HTTP 下令函数设置故障时仍能通过应用服务执行。
- **是否失去失败回滚？** 保留失败独立事件和未知异常回滚，故障注入检查确认无已写入领域副作用残留。
- **是否只有计划界面检查批准？** 应用入口再次核对批准、步骤和参数；未批准的背景调用不会产生领域命令。
- **是否一重试就重建任务？** 台账和历史接受事件均参与幂等判断，原命令来源与编号保留。
- **是否增加遮挡现场的新面板？** 来源与回执使用既有任务抽屉文档流，按需展开，16/14px 阅读尺度保持。
