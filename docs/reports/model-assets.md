## 资源与选择

复用现有 Kenney 骨骼人物、机器人部件、车辆和厨房器具。搜索并核对 Poly Haven、Kenney 与 Khronos glTF Sample Assets 的公开资源后，新增四组实拍PBR：草地、砖墙、地砖和木纹，各包含颜色、OpenGL法线和粗糙度；另引入旧木凳和灌木两个扫描模型。新增22个资源文件共10,711,166字节，均为官方CC0资源、1K纹理、本地依赖。单网格约95MB的扫描树候选未引入。

- [全部七组地材来源](../../frontend/public/assets/surfaces/SOURCES.md)：保留此前道路、铺地、墙面的九张图，新增十二张图。
- [扫描模型来源及许可](../../frontend/public/assets/community-real/SOURCES.md)：保留CC0正文和逐文件URL、大小、MD5、SHA-256清单。
- 获取脚本：`python scripts/fetch-community-assets.py`；只获取选定资源，校验官方大小、MD5及路径边界，不下载整个资源库。原三组材质继续使用`fetch-surface-assets.ps1`。

## 实际修改

| 范围 | 行为 |
| --- | --- |
| 社区环境 | 较少且尺寸分级的种植区域、街边木凳及停车位替代固定坐标摆放；布局由冻结建筑和通行数据确定，同一配置可复现 |
| 净空 | `communitySite.ts`按完整占地避让建筑、室内外通道、道路、门口、火点和集合点；空间不足或无效配置时省略装饰，不强行落位 |
| 资产比例 | `siteAssetFit.ts`检查完整变换后包围盒，保持等比、居中及贴地；叶片、把手和轮廓计入边界，不修改共享原型 |
| 建筑与室内 | 增加砖面基座、地砖与木纹材质；沿用已有门洞、楼梯、户门、厨具、人物和设备身份 |
| 地板闪烁 | 首轮浏览器发现厨房通行甲板与完成面共面；`passageDeck.ts`从路径甲板裁去已有房间、玄关及走廊地板覆盖区域，保留门槛，行走高度不变 |
| 画质与释放 | 低画质关闭PBR法线/粗糙度并隐藏灌木；模型请求失败保留基础木凳和种植面；退出取消请求并清理模型资源 |
| 资源联动 | 模型加载后触发暂停画面重绘；停车物件明确归为静态环境，消防车和救护车继续读取真实车辆状态 |

环境物件仅补充场景表现，不作为新物理障碍。通过避开冻结通行区保持既有仿真可用；没有以装饰物冒充新碰撞或处置功能。

## 适用限制

建模专项本身没有测量完整演练得分、低配帧率或1000人容量；随后两案例业务实跑及修复记录见[当前功能验收](current-release.md)。社区整体、人物与动态车辆仍是实时仿真风格，并非全部扫描级资产。完整住宅、所有门扇/家具/动态转弯的组合穿模、任意自定义地图净空仍需继续校准；当前几何与资源回归不能证明“所有情况下不穿模”。
