# 引导演练面板布局修复

## 定位

- 引导面板左侧固定为 12px，侵入观察、指挥和复盘模式栏；其定位没有跟随常驻工具栏的实际高度。
- 标题、操作和长说明共用一个滚动面，没有就近关闭按钮。
- 手机页头仍继承桌面三列网格，修改 flex 属性不起作用，导致标题被挤成省略号。
- 已结束场次仍可能显示“现场持续推演中”，用户容易误以为人员、车辆应该继续移动。
- 平板助手保留过多底部空间时，对话正文被页头和输入区挤压。

## 实现

1. `useSceneOverlayLayout` 使用 ResizeObserver 测量工具栏，将安全起点共享给引导、任务、预览与视角导航；组件销毁时释放观察器。
2. 引导面板位于左侧导航右边，不占导航命中区；宽度受可用视口约束。
3. 标题和收起按钮固定，正文独立滚动，支持 Escape 收起；收起后返回教练入口焦点。
4. 保留引导中的选择与输入，任务或预览展开时仅隐藏引导。结束后的三个操作按整行排列，正文和按钮使用 16px。
5. 手机页头采用明确的两行网格；关闭按钮使用可辨识的前景、悬停与焦点状态。
6. 修正结束与历史查看状态，不再显示实时运行提示；暂停时说明继续后才恢复移动。
7. 平板助手展开期间让出时间轴和底部工具区域给对话正文，关闭后恢复。桌面继续分栏，手机继续使用焦点隔离的全屏助手。

## 验证与自我拷问

- 是否只是提高 z-index 遮住其他按钮？否。分配了独立导航边距和工具栏下方安全起点。
- 滚到最下面还能关闭吗？可以，关闭按钮不在滚动正文内。
- 任务展开是否丢失引导状态？未卸载引导；只在用户主动收起时结束该面板实例。
- 是否改动人员、车辆仿真数据？没有；沿用原命令、任务与模型更新链路。
- 使用真实前端组件、隔离示例数据检查 1440、1024、768、390 宽度的引导、任务切换、预览和助手，未修改真实场次或调用大模型。
- 前端生产构建通过。范围为导演台面板布局和状态提示，不据此声称其他所有业务页面已完成全面验收。
