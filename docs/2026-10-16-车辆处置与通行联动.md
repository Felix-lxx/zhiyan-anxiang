# 车辆处置与通行联动

本轮围绕演练的车辆执行链审查和修改代码，重点是将“到场”与“处置完成”分开。没有改动真实社区数据，没有新增遮挡现场的浮窗。

## 实际入口与操作

在运行中的连续空间场次打开 **处置任务 → 车辆调度与到场处置**，或者点选三维车辆后进入任务面板。

### 消防车

1. 选择消防车和道路节点，预览路线。路网宽度、封锁和其他车辆占用可能阻止调度；查看预览原因后调整。
2. 确认行程。通道内有居民时，入口先暂缓放行；原有行人走出后车辆出发。面板显示等待原因，不把等待当成行驶。
3. 到场后查看水源与火点条件。车辆需要处在距可用消火栓及火点各 25 个场景单位以内，水带和射流不能穿过楼栋。
4. 点击“预览喷水处置”，确认后连续工作 45 个演练秒。支持提前停止；水源失效立即停止。
5. 观察三维水带、水流、火势及烟气变化。喷水开始、停止、完成都有事件，指令回执与真实持续时间一致。

### 救护车

1. 先完成居民疏散和集合清点。可接运对象是已核验的重点人员，或累计烟气暴露超过 5 的居民。
2. 将救护车驶至该集合点同侧出口，在面板选择居民并预览接运路径。
3. 确认后，担架组沿集合通道从车边前往居民，再携带居民返回，最后完成 8 秒装载。尚未接到人时居民留在原位。
4. 上车后选择另一出口，预览并确认转运行程。车内人员跟随车辆状态；不能取消行程后丢弃接运责任。
5. 到达另一出口后预览医疗移交。8 秒卸载交接完成后才清空车内人员并生成完成证据。

暂停、历史回放和结束场次不允许下达新动作。查看历史位置不会推动现场时钟。

## 代码职责

| 模块 | 本轮职责 |
| --- | --- |
| `fire_environment.py` | 从事件构造分段环境曲线；实况、路线风险、预演、回放和机器人温度采样读取同一规则 |
| `vehicle_traffic.py` | 路段预留、行人清空、车辆通行与自动解除；检查其他车辆路线冲突 |
| `vehicle_rescue.py` | 处置条件校验、接运阶段、车内责任和移交位置的事件投影 |
| `operations.py` | 复用统一命令事务与版本校验，推进动作并写入完成／中断事件 |
| `command_feedback.py` | 将动作受理、执行进度、停止、完成映射到回执，不在点击时提前完成 |
| `VehicleDispatchPanel.vue` | 一个任务面板完成行程、处置、原因说明和最近记录展示 |
| `rescueVisuals.ts` | 水带、实例化水滴、担架、接运员及装卸运动，仅表现服务端确认的位置 |

动作沿用既有不可变事件、持久化命令、Outbox、WebSocket 和回放链路，不新增另一套浏览器端仿真。处置实体按 ID 增量推送；每辆车只保留最近 6 项面板记录，完整历史仍在事件与处置状态中。

环境规则为有效喷水时火势指数每秒下降 3.2、烟气半径每秒下降 0.35；到零后不继续生成火势。未喷水时保留原有资源就绪、断电、水源故障对应的增长规则。机器人报警采样改为读取相同环境曲线，并要求连续三次温度达到规则阈值。

## 页面约束

按 Impeccable 的现有界面规范保持深绿导演台：正文 16 像素、说明 14 像素、按钮至少 44 像素；字段按面板宽度换列，按钮自动换行。到场处置放在原任务抽屉内，历史记录折叠，预览沿用单一空间预演面板。没有新增绝对定位控制层。

## 自我拷问与验收

- **是否只是喷水动画？** 不是。环境状态实际下降，水源故障终止效果；机器人采样也不再沿用独立的固定升温公式。
- **是否原地点击就完成转运？** 不是。未清点不能装车，装载需要往返和交接时间，同一出口不能完成医疗移交。
- **是否直接移动车辆穿过行人？** 新调度先预留整条通道并等已有行人走出。真实居民场次验证入口等待、清空及车辆放行。
- **是否增加了第二个人物？** 接运途中隐藏原居民外观，由担架模型表现同一居民；车内不再显示独立行走模型。集合牌按实际节点统计，离开集合点后不继续占用集合位置。
- **是否通过刷新才能看见变化？** 动作、人员位置和回执由原实时同步通道推送，断线沿用版本恢复。旧缓存增加处置投影版本检查，避免返回升级前快照。
- **是否为本轮做了大规模全量测试？** 没有。验证范围集中在车辆调度、喷水、接运、真实通道互锁和助手上下文：24 项后端检查通过；生产构建通过；1440 / 390 宽度下任务面板无横向溢出、按钮无相互重叠，三维效果没有页面脚本异常。
