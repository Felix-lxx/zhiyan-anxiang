# P2 充电棚放行编排交付记录

日期：2026-11-09。

## 本批实现

- 资源与空间条件允许时，保留立即撤离和压制后撤离两种不同行动。无法提供压制方案时，页面呈现真实原因。
- 压制方案以楼栋为批次，下一栋等待前栋人员实际到集合点。跨出口、重点护送与机器人通知共享依赖图。
- 每栋放行前核对有效供水和喷水。前次喷水结束后，任务图可发起新的正式喷水动作；火势已归零时等待残余烟气消退，不重复申请无效喷水。
- 使用机器人通知时，广播点真实到位后才能放行本栋；机器人前往下一栋同样等待前栋到场。楼栋次序沿用机器人路线与电量预览的次序。
- 水源失效触发待复核；保留已经受理的移动、暴露和事件，不再向后续批次发令。
- 执行工作区展示每批人数、到场人数、状态、具体等待原因和定位入口。候选展示累计暴露及预演内末位到场时刻，未全员到场时不称为全程耗时。

## 代码边界

放行规则抽到 `backend/app/services/agent_release.py`。协调器仍负责审批、资源登记与正式命令；居民、车辆及机器人继续由原领域服务驱动。没有增加新的数据库表、角色、弹窗或独立指挥页。

## 独立供水与水带避障跟进

### 领域与兼容

新冻结世界增加 `water_resources.version = 1`，保存水源 ID、初始状态与主水源 ID；`environment.hydrants` 投影各水源实时状态。旧冻结世界继续沿用全局水源故障规则，既有事件、轨迹和得分不重写。本次不需要数据库表迁移。

`VehicleCommand.water_source_id` 贯通预览与正式命令。自动选择时按可连接路径长度选择；前端确认会固定预览返回的水源 ID。无法识别、失效、超长或无法连接的指定水源会被拒绝，不回退到其他水源。`EventInject.hydrant_id` 指向本场冻结资源；注入时再次核对对象归属与当前状态，跨场次或重复失效不会写入事件。

环境时间线按喷水动作绑定的水源判断作用：其他水源失效不停止该动作；所用水源失效时停止喷水并写入处置回执。后续放行核对水源、有效喷水和批准的供水身份。智能体重规划、影响说明和助手引用读取相同状态，停止自动发令时保留已受理的行程、暴露及原始证据。

### 空间与模型

`water_resources.py` 使用冻结楼体和可见连接图计算水带路线，按实际绕行长度限制 25 米，并预留 0.18 米楼体净距。路径从消火栓实体出水口接到按车辆位置与朝向计算的泵口；不是连接两个模型中心点。三维沿服务端路径保留拐角，中间段贴地，不用样条抄近路穿墙；以不超过约 0.08 米的采样间隔构建管体。

新冻结路网同时记录消火栓实体包围范围。车辆路径检查包含设施避让，道路仍使用原通行宽度要求，设施净距则使用与模型一致的车身尺寸。楼体检查保持原有规则，历史已受理轨迹不重新拟合。
