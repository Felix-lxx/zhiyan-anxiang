# 智能体执行监护与护送模型升级

## 使用入口

打开演练的“安巷指挥助手 → 目标计划”，选择范围并生成方案。一次展开一个候选方案核对路线、预测结果和护送资源；确认后进入“执行”。展开步骤可以查看具体居民、所在通道、排队时长、会合状态、责任人和原始事件。点击人员旁的“定位”返回三维现场，楼内人员沿用原有自动透视定位。

## 本轮实现

1. 增加只读执行投影 `agent_execution.py`。计划、命令台账、居民状态和事件关联读取，按受阻、未到场、暴露和排队优先呈现人员。一项步骤最多展示六名重点人员、四条关联事件，保留总人数与其余人数；执行范围不因展示限制而缩减。
2. 停止自动下令与停止人物移动分别处理。停止计划后仍读取已经受理的命令回执，不将旧的步骤进度留在界面上；冻结现场继续使用演练暂停。
3. 执行监护根据居民、护送员位置和命令进度判断变化。运行中连续 45 秒未观察到变化时提示定位检查；不因此取消指令或未经确认改变出口。暂停、停止或人工接管后的计划不会误报该提醒。
4. 生成方案展示值守总量、已占用量和所需护送人数。没有可用值守员时禁止批准护送；历史方案在执行前再次校验。所有人员到场但未清点的场次结束时，计划归为未完成，不再无限停留在等待清点。
5. 护送三维实体按固定值守 ID 复用，同一值守员的历史任务不再生成多个身体。完成护送后保留最后的服务端位置，显示集合区域待命；接新任务继续复用模型。历史数据缺少值守 ID 时仍按原任务身份显示。
6. 会合路线取服务端完整通道折线，保留走廊、楼梯和绕楼拐点；无有效路径不补画两点直线。只显示选中目标的会合路线，楼内路线随透视控制显示。点击值守员可查看责任说明并关联目标居民。
7. 骨骼人物与轻量备用人物均增加护送同行手势；手势仅改变局部骨骼，不改变人员位置、模型比例或服务端会合条件。复用既有本地模型资源，不新增网络下载依赖。
8. 修复目标计划轮询在面板反复开关时可能留下多个定时链的问题；切换场次清空旧计划、选择与错误，丢弃旧请求返回。切换候选方案时清除上一方案的三维路线，避免确认方案与现场路线不一致。

## 编排边界与联动

本轮沿用一个持久化目标工作流：目标解析与候选预演、人工批准、并行的居民分流/护送及机器人支线、命令回执、人工清点。执行监护是确定性的查询和状态检查模块，不另建能直接写入场次的模型代理。模型仍只在授权后解析目标；位置、受理、到场和广播结果由现有领域引擎与事件决定。

新投影不写事件，也不推进演练。调度器继续推进步骤，前端沿用三秒读取目标计划，三维位置沿用场次实时通道。因此面板描述与三维画面可能相差一次读取间隔，而不是宣称它们在同一帧完成同步。

## 界面排版

保留深绿导演台和既有单助手面板。候选方案只展开选中项，执行人员与证据只展开当前步骤；没有新增弹窗或绝对定位按钮。步骤标题、状态和定位动作允许换行，内部人员列表使用独立文档流，避免被原步骤标题的 flex 规则压成半幅。正文 16px，辅助说明 14px，操作目标至少 44px。

定位进入居民第一视角或对象详情时，暂时收起独立对象导航，避免导航选择框被详情面板覆盖；第一视角保留上一人、下一人和退出按钮。关闭详情后恢复对象导航。

## 自我拷问

- 指令已受理是否就算完成？不算；步骤显示真实命令状态，到场与清点分别记录。
- 居民停住但护送员正在接近是否误判停滞？监护签名同时检查护送员坐标和高度，正在接近会更新进展时间。
- 停止计划后现场继续移动，界面是否还显示旧进度？执行查询读取当前命令台账，停止只影响未来下令。
- 同一值守员换任务是否复制身体？有固定身份的任务合并为一个显示实体；历史任务仍保留用于证据。
- 去掉直线连线是否等于彻底解决所有穿模？不等于。此次消除了会合提示线跨楼和重复身体问题；移动继续使用现有服务端通道与确认路径插值，未替换完整碰撞系统。
- 是否把布局夹具当成真实演练结果？没有。后端流程检查验证资源、执行与清点；浏览器夹具只验证真实组件、三维资源载入、定位事件与布局。
