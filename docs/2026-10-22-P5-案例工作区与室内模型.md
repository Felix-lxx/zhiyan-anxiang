# P5：案例工作区与室内模型

日期：2026-10-22。延续 P4 的任务图、资源归属与指令回执，本阶段整理案例入口、楼内操作及空间表现；不新增独立指令执行器。

## 1. 可操作入口

1. 首页选择“充电棚火灾”或“住宅厨房火灾”。已有案例直接切换；没有案例进入预选模板的准备页，仍须确认创建、配置和发布。
2. 准备页选择住宅、楼层、房间；可点击三维厨房台面或地面标记选房间，撤销仅恢复本次火点选择。保存后创建新场次冻结配置。
3. 导演台“查看楼内透视”显示楼栋、楼层选择。“画面设置”展开原有画质选项，不另外弹出覆盖面板。
4. 厨房场次“楼内烟气与门控”打开唯一工作抽屉：切层、读取分区烟气、定位居民、选中本层人员、开关房门。选人后回到原空间路线预演，确认仍使用现有居民命令链路。
5. 复盘页在画布上方切换观察楼层。分支和双世界入口沿用既有流程，本阶段不改变分支计算规则。

## 2. 空间一致性

### 2.1 新场次房间布局

`indoor_layout.kitchen_rooms` 是新厨房房间范围的唯一计算入口。先预留楼梯宽度、楼板洞口及侧向余量，再布置两间厨房。每个房间独立连接门前走廊，随后连接公共走廊和楼梯；不再从房间直接斜穿另一房间连接中心节点。

火源位置、房间节点、房间烟气范围共享该几何结果。新冻结通行图标记 `indoor_layout_version=2`。住宅尺寸无法容纳通道与房间时，准备校验、预览和创建均通过同一火点解析入口拒绝配置。其他不适合厨房布局的楼栋保留普通住宅通行图。

已有场次不重建拓扑，原始空间、位置、暴露、事件和评分保持不变。厨房环境模型仍是分区训练规则，并非流体动力学计算；房间增加门前分区后，新场次烟气传播由新冻结连接推进。

### 2.2 模型表现

- 楼板从楼梯通道生成开洞，楼梯不再从完整实心楼板中穿过。
- 台面、橱柜、后墙在创建前检查通道包络；小空间没有安全位置时保留可选择地面标记，不强行塞入家具。
- 门框根据冻结房间至走廊的实际连接定位；门扇绕铰链旋转，不平移穿过通道。
- 楼层几何带楼栋和高度区间，切层保留下行梯段；人员和护送员不因楼梯中间高度而突然隐藏。
- 第一视角镜头使用已有沿路径插值的人员位置，避免再对相机做直线平滑而切过转角。
- 厨房细节按层延迟创建，已经创建的楼层复用；火焰仅在对应楼栋与起火层的剖面显示。

## 3. 页面与联动修复

沿用 Impeccable 的单工作区、渐进展开与正文可读性原则：纸色准备页、深绿导演台，16px 操作与正文、14px 辅助说明、44px 主要触控目标。工具区允许换行，其高度继续交由既有布局测量管理；楼内抽屉与助手、任务、预演互斥，不新增固定浮窗。

实页检查发现历史链接会过滤掉已经改为草稿的原场景，继而误开另一个已发布场景。现已按明确的场景与场次编号加载历史；指定编号不存在时显示错误，不静默替换。手动切换其他场景不沿用旧链接的场次编号。

首页同时修复状态矛盾：预览读取中显示核对状态，预览失败时引导检查配置；不再仅凭发布状态显示“已冻结，可以开始”。真正的冻结仍发生在新场次创建时。

## 5. 自我拷问

**只有按钮，没有执行吗？** 楼层控制改变同一三维现场的可见几何与观察位置；选人进入已有预演命令；门控沿用服务端校验、事件和回放。隔离页面的门控验证不能代替后端执行验证，因此分别记录。

**是否只是把穿模藏起来？** 新场次同时调整房间拓扑、火源坐标与烟气范围，楼板按真实梯段开洞；家具先检查通道再创建。旧场次只能兼容显示，不能为了画面美观改动历史拓扑。当前不是完整物理碰撞求解器，任意地图和所有极端相机姿态仍需实际观察。

**两案例是否另起一套系统？** 没有。模板准备、冻结场次、智能体批准、人物命令、任务证据和复盘继续使用现有框架。厨房入口不代表系统已经自动创建或运行厨房演练。

**可否宣称全部升级完成？** 不可以。P6 仍需完成两个案例的同起点分支对比与完整演示验收；本阶段不新增车辆智能体工具、真实室内喷水或第三套场景。
