# 准备与演练联动升级

## 本轮交付

### 历史记录不再拖累运行现场

- 新增 `GET /communities/{id}/drill-history`，数据库完成跨场景筛选、稳定排序、计数和分页；每次最多 100 条，界面默认 20 条，首页仅取 3 条。
- 从创建事件 JSON 提取冻结人数标量，关联最终评分，不读取整个居民世界、不扫描所有场次事件、不推进仿真。
- 返回独立的最近未完成场次，不再因为首页只加载三条而遗漏继续入口。
- 客户端搜索防抖，取消过期请求，分页加载时禁用重复翻页，错误可重试。CSV 只导出本页并明确标注，避免把部分记录说成全部。

### 缺项定位能进入实际修改状态

- 缺楼栋、水源或集合点：地图切换到对应设施放置工具；不会自动创建对象。
- 路网断连：选中具体不可达节点，显示坐标和节点编辑表单；目标被删除时明确提示重新检查。
- 场景参数缺项：带场景 ID、配置步骤和字段进入场景准备，滚动并聚焦真实输入框。
- 完整性校验和发布面板提供“定位修改”；未保存输入仍由原有离开确认保护。
- 预览失败不再继续显示旧的路径建议和风险等级。

### 校验与演练使用相同规则

- 抽取 `scene_validation.py`，复用现有参数 Schema，校验时间、人数、水源状态、通道状态和楼梯宽度。
- 检查起火点确实存在、是充电棚且属于场景引用的社区版本。
- 准备检查、手动校验、发布、新场次创建共同调用；新场次在冻结世界之前拒绝失效配置。
- 基础设施完整性、道路连通检查仍与发布参数校验区分。故障水源、阻断道路可以是有意设置的训练条件，不能因风险状态本身禁止训练。

### 修复任务丢失

修改已发布场景派生新草稿时，以前只复制决策点和选项，没有复制 `DecisionTask`。现在复制任务标题、目标、期限，并关联新决策点和新版本；旧任务及旧场次证据保持不变。

## 自我拷问

- 分页是否仅把全部数据切片？不是，SQL 执行 `LIMIT/OFFSET`；没有逐场景 `summary` 请求。非常深的页码仍可能受 OFFSET 成本影响，不能宣称无限规模。
- 选择筛选条件后会不会显示上一条件的结果？请求取消与序号检查阻止旧响应覆盖；新请求期间清空旧页并提示加载。
- 校验是否只看参数非空？不再如此；共用 Schema 和真实起火对象查询。并未把它包装为现实消防安全认证。
- 修改后能否真的带着任务进入下一轮？针对性用例验证新草稿保留任务，任务关联新决策点，旧版任务仍在。
- 是否本轮完成了所有三维建模升级？没有。本轮改善的是三维场景输入、准备页面和演练任务联动，没有替换模型资源或验证千人长场次帧率。
