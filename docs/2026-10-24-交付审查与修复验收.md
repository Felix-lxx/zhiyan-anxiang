## 模型与优化的比较口径

本项目是规则化空间/环境/评分与路径规划，不包含训练得到的机器学习权重，因此没有新增训练集、精度或泛化指标。

| 同口径检查 | 原行为 | 修改后实际结果 |
|---|---|---|
| 编辑人口为24，进入示例入口 | 入口把人数覆盖为60，且可能取得旧版本 | 回归断言参数为24、冻结人口为24、任务3项；再次进入版本ID不变 |
| 同名厨房资产503后重试，再创建两个实例 | 被拒绝的缓存Promise会继续拒绝 | 前端回归：第2次下载成功；两个实例总共2次请求（含第一次失败），成功源共享，实例不同 |
| 模型装入1×0.9×0.6包围盒 | 未检测无效尺寸和退化模型 | 实测包围盒不超限、底部对齐0；NaN和非法名称不发请求 |
| 退出厨房时仍在下载 | 请求继续 | AbortSignal实际触发；异步结果不挂到已销毁场景 |
| 现有移动几何 | 沿确认路径拐点，断路时校准到服务端 | 保留逻辑；人物、门洞、家具净距、楼梯开洞和车辆测试通过 |

没有把上述可靠性改善换算为帧率或算法精度提升。Three.js 引擎生产分包仍约606.97KB（gzip154.59KB）；本轮未对低配硬件、1000人长场次、多进程PostgreSQL做性能基准，不能宣称已达到企业容量指标。没有替换成未经校验的装饰模型。

## 启动、升级与回滚

1. 备份现有数据库和部署配置；不把真实.env/数据库提交仓库。
2. 后端执行 `python -m pip install -r requirements.txt`；前端执行 `npm ci`。Python3.11+/Node22按README准备。
3. 重启后端，以便JWT校验、Origin、日志脱敏及修补依赖生效；生产环境配置独立JWT_SECRET、管理员密码、HTTPS CORS_ORIGINS。前端 `npm run build` 并发布 dist。
4. 本轮没有表结构变更。旧场景缺标准任务时，使用已有 `POST /scenes/{id}/repair-tasks` 创建/修复草稿，再校验发布；已冻结历史场次不改写。示例入口自身会修复标准任务并避免返回无任务历史快照。
5. 现有服务启动命令见README。临时验收服务位于 `http://127.0.0.1:5188`（API8018），使用独立数据库。它不是生产配置。
6. 如需回滚，恢复上一交付源码和依赖锁文件并重新安装/构建；保留数据库备份。本轮原历史场次未被重写。
