# 个人中心与页面布局验收

## 对“是否全部正常运行”的回答

不能把上一轮核心链路通过等同于全部功能或生产上线验收。本轮在现有 Vue/FastAPI 框架上完成个人中心可保存功能与主要页面的布局整改，并重新跑通场景—参演任务—封路—分支—评分—导出的实际流程。未实现的生产账号管理、并发扩容和高精度仿真没有列入完成范围。

## 本轮真实功能

| 功能 | 实际行为与保存位置 |
| --- | --- |
| 显示名称 | 写入当前用户 `users.display_name`，保存后首页账号入口同步显示；登录名和事件操作人标识不变 |
| 所属单位 | 写入当前用户 `account_preferences.organization`，可留空 |
| 默认社区 | 保存前检查该社区属于当前账号；下次返回首页或重新登录时优先选中；不存在时退回可用社区 |
| 文字大小 | 舒适正文 16px、大字 18px，主要标签及辅助说明随之调整；不整体缩放三维画布 |
| 减少界面动画 | 保存到服务端，抑制 CSS 过渡和装饰动画，不暂停仿真人员移动 |
| 我的演练 | 后端按账号所属社区查询真实数量和最近六场记录；未结束场次进入现场，结束场次打开复盘 |
| 搜索与继续演练 | 复盘列表按名称/状态筛选，空结果提示可恢复；未结束场次有独立继续入口 |
| 失败与并发编辑 | 保存失败保留输入、不显示假成功；资料版本冲突提示重新读取，避免旧页面覆盖新资料 |
| 离开保护 | 修改未保存时，切页或刷新提示；支持撤销修改 |

新增接口：`GET /account/profile`、`PATCH /account/profile`、`GET /account/activity`，均位于 `/api/v1` 下并要求登录。资料接口拒绝额外字段，不能提交角色或密码变更。新增偏好表是增量创建，不改写既有业务表结构或本地密钥。

登录与权限区清楚说明当前仍使用开发环境账号，不提供虚假的改密码按钮。活动统计是账号管理的社区场次记录，不伪称用户亲自参与时长或学习成绩。

## 布局整改

- 个人中心不再限制在左侧 760px 小区域：工作资料与阅读设置在左，真实演练记录及登录说明在右；手机按顺序单列。
- 首页保留纸面与深绿的既有设计，不堆同尺寸仪表盘卡片。标题与长名称允许换行，手机三维/效果图的高度不再被桌面规则覆盖。
- 场景准备提前折叠三列；预览底部指标按实际容器换行，减少过小字。手机五个步骤按网格排列，配置表单在预览下方。
- 复盘在中等宽度使用两列加底部证据；手机三维现场优先。工具栏回到正常排版流，不绝对覆盖画布，不挤出空置的第三列。
- 历史表格保留可横向滚动的完整数据和键盘焦点入口；未压缩字体以强行塞入手机宽度。手机首次使用提示不再将正文挤成窄列。
- 主要页面使用共同阅读令牌，不对三维空间标签、所有历史组件宣称已逐项清除小字号。

## 验收证据

- 后端全量测试：68 项通过（包含 3 项新增资料持久化、验证/版本冲突、账号数据隔离测试）。
- 前端单元测试：14 项通过；类型检查与生产构建通过。
- 个人中心专项：真实保存并刷新恢复；模拟 503 保存失败时输入保留、数据库未变；大字设置实际计算字号检查；未保存离开取消；历史筛选与清除通过。
- 页面检查：首页、个人中心、历史记录、场景准备、复盘、社区管理、使用说明；主要页面覆盖 1440、1024、390 像素宽度；无文档横向溢出。对复盘工具栏位置、三维区域最小宽度另有断言。
- 既有全流程浏览器验收：登录与密码显示切换、场景预览和校验、手机登记/接收/到达/提交真实证据/上报异常、道路预览确认封锁、历史回放和可编辑分支、结束评分和真实报告下载均通过；浏览器脚本异常为 0。
- Impeccable 静态检查：新增个人中心、首页改动和排版文件无命中。截图复核发现并修复旧样式优先级导致的复盘中间列挤压。

脚本：`frontend/tests/account-layout.e2e.mjs`、`frontend/tests/atlas-pages.e2e.mjs`。截图：`output/playwright/account-layout/`、`output/playwright/account-workflow/`。仅使用独立测试数据库 `tmp/account-layout-review.db`，没有改动用户现有业务数据库或模型配置。浏览器测试需明确设置测试环境的 `QA_PASSWORD` 等参数；不能不加区分地对真实社区执行造数测试。

## 自我核查

1. 是否只是多了表单？不是，服务端持久化与刷新后的字段、偏好、显示名称都经过浏览器和接口验证。
2. 是否泄露其他账号的数据？默认社区选择和演练记录查询均有所有者约束，测试覆盖第二账号不能读取第一账号的记录或使用其默认社区。
3. 是否用“视觉上不重叠”代替业务验收？没有，旧业务闭环重新实操通过；但这不替代所有场景组合和多设备压测。
4. 是否保证所有功能已生产可用？没有。正式双角色账户、权限收敛、密码生命周期、多实例状态协调与多人压力验收仍待实现；规则火灾模型不等于真实火场安全结论。

## 使用与后续

重启后端以创建新增表并加载接口，刷新开发前端或重新构建部署前端。点击首页右上角账号进入个人中心。保存默认社区和阅读设置后，可回到首页直接验证。

下一轮优先处理正式双角色账号与权限、空间预览版本校验及多人联动负载测试；页面方面继续分区拆除旧样式的重复覆盖，避免后续新增功能重新引入布局争夺。本轮不声称已重构所有历史 CSS，也未提交或推送 GitHub。
