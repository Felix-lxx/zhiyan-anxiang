# 安全与演练可靠性修复

## 本轮实现

安全配置在 Settings 构造时校验。非 development 环境必须更换默认签名密钥和管理员密码，设置明确的 HTTPS CORS 来源；数据库结构初始化失败时停止启动。已有管理员不得通过“无密码字段”回落到开发初始密码。

新增 participant_invitations、socket_tickets 和 security_rate_windows 三张表，由现有幂等建表流程创建。邀请具有独立随机的 128 位凭证、到期时间和撤销标记，数据库只保存哈希。首次展示后无法从数据库恢复原文；重新打开导演台生成新的独立邀请，已有邀请不会被隐式撤销。显式更换邀请会先撤销全部旧邀请，再生成新链接。

加入码解析、登记、邀请创建、票据签发、登录与刷新采用数据库原子计数限流，多个应用进程共享计数。信任边界是服务端看到的客户端地址，不直接信任任意转发头。生产反向代理应按部署拓扑配置可信代理地址，避免所有参演设备被聚合成一个来源。

WebSocket 必须先通过 HTTP 获取 30 秒一次性票据，握手时通过条件删除原子领取。票据保存账户会话或邀请引用，不保存访问令牌。实时读取持续核对账户、登录会话及邀请的有效性；凭证撤销会终止现有连接。重连重新签发票据，保留事件序号追赶和实体补丁协议。

管理端 Access Token 仅在内存保存；刷新页面使用 HttpOnly 刷新 Cookie，Web Locks 可用时跨标签页串行刷新。生产 Nginx 添加 CSP、禁止嵌入、关闭 API 访问日志并代理 API/WebSocket；默认前端 Docker 构建使用同源 /api/v1，前端刷新路由由 Nginx 回退 index.html。开发 Vite 的 CSP 为热更新和跨端口本地 API 保留必要权限，不能用于生产托管。

所有参演反馈均要求有效 ParticipantSession，事件日志不再充当认证数据库。旧版任务提交增加责任角色与证据校验，新版任务继续使用接收、到位和核验流程。

## 人员与仿真

新场次冻结四个命名的模拟值守岗位，具有编号、角色、初始位置和可用状态。导演可将空闲岗位绑定到本场物业/网格员参演者；一个身份只能绑定一个岗位，执行中不能交接。每次交接写入 staff.bound 事件。三维护送员关联岗位与责任人，完成后从上次到达点继续下一项任务。岗位绑定表示训练责任，不表示真实人员 GPS 位置。

人员、搜索和智能体计划共用相同容量计算。模拟引擎不再为每个目标无限创建新的可用人员；资源已占用时计划等待释放。

保持半秒时间步和逐路段容量规则。本轮将拥堵寻路缓存按时间步失效，节点与边端点继续使用冻结输入，只复制可变的运行字段；恢复检查点时不重复创建全量初始居民。每个世界保留最多八个时间检查点，避免未来预演覆盖当前现场的唯一检查点。静止且环境风险已稳定时对暴露直接积分，遇到下一条事件或准备结束时间恢复正常步进。

新持久快照只保存运行状态和冻结世界引用，读取时从创建事件恢复世界数据，避免每五秒重复存储整份建筑、人口初值与拓扑。旧快照仍按原格式读取，不批量改写历史记录。

这属于现有确定性引擎的增量优化，并未替换为独立离散事件调度引擎，也未宣称千人、多实例生产容量已经验收。

## 页面与升级操作

低于 760px 高度的桌面窗口收起空间工具文字，保留按钮可访问名称。预演改为底部滚动区域，任务和对象详情仍位于独立预留区域；主操作与正文继续使用原有 16px/14px 阅读令牌，所有关键控件维持至少 44px 点击高度。

1. 重启后端，让建表流程创建新增表；原场次和事件保留。
2. 刷新浏览器，清除旧的持久访问令牌并通过现有刷新会话恢复登录。
3. 打开导演台“手机参演”，复制新链接。所有 UUID 后六位旧邀请均已停用。
4. 生产环境设置 APP_ENV、JWT_SECRET、BOOTSTRAP_ADMIN_PASSWORD、CORS_ORIGINS，并在 HTTPS 反向代理之后运行。密钥与数据库密码均由部署环境提供。

接口调整：邀请创建由 GET 改为 POST /drills/{id}/participant-invite，DELETE 同路径撤销全部邀请；管理与参演端分别通过各自的 POST socket-ticket 接口签发票据；WebSocket 只接受 ticket。其他演练命令和增量同步格式保留。

## 自我拷问

本轮必要验证：安全与实时同步、增量世界、值守复用共 22 项，目标计划工作流 5 项，刷新会话原子轮换 1 项，前端轻量回归 26 项通过；生产构建通过。隔离浏览器检查覆盖 1440×900、1366×650、1024×768、390×844，画质/透视工具与任务抽屉无覆盖，未出现页面脚本异常。精简快照恢复和值守复用另做两项定向复核。前后端均已启动，健康接口返回 healthy。

- 邀请是否仍能从场次 ID 推导？不能；凭证独立随机生成，数据库只存哈希。
- 撤销是否仅影响下一次登录？不是；现有实时连接也持续检查凭证引用。
- 参演者退出后能否从事件日志恢复身份？不能；只认可有效参演会话表。
- 护送资源是否仍会凭空增加或返回基地？资源固定占用与释放，复用从上次完成位置开始。
- 性能优化是否跳过移动、排队或封路事件？正常移动仍按半秒推进，稳定区间只跳到下一状态变化边界。
- 页面是否只是减少字号塞入更多内容？短屏通过布局让位与独立滚动处理，维持既定阅读尺度。
