# 演练联动、模型恢复与展示审查

## 本轮结论

现有代码已具备服务端版本化状态、增量推送、指令记录、连续路线移动、集合清点、分支比较与三维骨骼模型，不是只有界面按钮。本轮优先修复这些能力之间的使用断点，没有引入新的仪表盘，也没有把未验收的功能统一标记为完成。

保留本轮开始前已有的首页、助手、抽屉和文档修改。本轮新增代码集中在 `OperationsCenter.vue`、`DigitalTwinArena.vue`、`director-layout.css` 与 `three/actorAssets.ts`。

## 已落地的修正

| 环节 | 原有问题 | 本轮修改 |
| --- | --- | --- |
| 空间预演 | 普通 HTTP 超时过长；取消后网络请求仍可能回填 | 独立 15 秒超时、AbortController、请求序号与场次校验；取消、暂停、复盘和卸载使旧结果失效 |
| 任务派遣 | 从处置任务派机器人绕开空间预演 | 任务派遣进入同一路线预演与确认流程，保留服务端事件序号校验 |
| 指令反馈 | 切换场次后旧请求可能显示成功/错误提示 | 只在原场次仍有效时应用结果和提示；结束场次成功后才进入复盘 |
| 队列状态 | 已受理状态未计入待完成项；提示容易被理解为立即移动 | submitted、accepted 纳入执行入口计数；提示明确排队、移动、受阻的区别 |
| 居民/助手上下文 | 选中时的详情不随状态变化更新 | 更新位置、行为、目标出口、累计排队和暴露；同步所选对象上下文给助手 |
| 预演排版 | body 级浮层绕过导演台布局管理 | 返回三维视口；统一预留顶部、底部时间线和工具入口；其他空间面板互斥显示 |
| 精细模型 | 加载失败的 Promise 一直缓存，无法现场恢复 | 清理失败请求缓存，记录失败挂载任务，去重重试；保留轻量模型与既有位置 |
| 部署路径 | 环境 GLB 从域名根目录请求 | 使用 Vite BASE_URL，适应子路径部署 |
| 图形恢复 | 上下文丢失提示混同初始化失败；恢复计时器缺少清理 | 分离恢复状态，恢复后同步最新实体，卸载时清理定时任务 |
| 表达准确性 | 规则暴露量表现为百分比；暂停提示称车辆也受控 | 展示实际规则量；运行提示改为实际受控的居民和机器人 |

## 使用闭环

1. 进入正在运行的演练，点击对象或在任务中选择派遣机器人。
2. 检查路线预演的风险、队列、用时和预计影响；此时没有下达执行指令。
3. 点击确认，提交预演对应的事件序号。现场发生冲突时重新预演，不静默使用旧计划。
4. 在任务入口查看指令实际执行状态。加入队列不等于已经到达，广播等行为仍受服务端到达条件限制。
5. 跟随或选择居民查看实时位置、等待和暴露；打开助手时使用该对象的最新上下文。
6. 模型网络失败仍可使用轻量现场；点击“重试精细模型”恢复外观，不重建演练。

## 代码审查后的后续重点

| 优先级 | 依据 | 后续工作与验收 |
| --- | --- | --- |
| P1 | `realtime.py` 的数组作为整体替换 | 大人口场次仍会传输完整居民数组。按实体 ID 增量传输，并保留重连全量校准；记录带宽、快照耗时和端到端延迟后再设指标 |
| P1 | `DigitalTwinArena.vue` 对 simulation 进行深度监听，并在更新周期调用多个图层更新 | 分开路网、环境、人物版本，减少只改人物坐标时的重复图层检查；不能以动画预测替代服务端位置 |
| P1 | `SpatialTrainingLab.vue` 与导演台分别管理预演/提交状态 | 将超时、取消、错误类型和场次隔离抽为共用 composable，避免训练教练与空间操作逐渐分叉 |
| P1 | 消防车、救护车在 `loadEnvironmentAssets` 中作为静态环境资产挂载 | 车辆调度需独立队列、路径、停靠和到场事件模型；目前不能算可执行交通主体 |
| P1 | `DigitalTwinArena.vue` 与 `domain/drill.ts` 有重复且不完全相同的居民、机器人、空间类型 | 统一服务端字段类型，补齐室内高度、楼层、位置和排队字段，逐步消除本地接口漂移 |
| P2 | 主三维组件同时管理拾取、渲染、图层、相机与详情面板 | 按图层与交互职责拆分；保留同一状态源，不另外创建独立仿真 |
| P2 | `styles.css`、`director.css`、`atlas-director.css`、可读性样式仍并存 | 继续删除旧的重复几何规则，限定 director-layout 为定位唯一来源，避免靠越来越高的选择器覆盖 |
| P2 | 环境资产与人物资产的恢复能力不对称 | 后续为环境装饰提供按资源重试与释放；本轮原地重试只覆盖人物和机器人 |

以上为代码检查确认的改进点，不等同于已经测出的性能瓶颈。长场次、多客户端和多楼栋真实场次仍需针对性验收。

## 自我拷问与设计复核

**是否只是新增按钮？** 不是。重试会重新发出失败模型请求并挂载；派遣入口实际改用预演链路；旧请求被中止并按场次隔离。

**是否把“成功提交”说成“目标完成”？** 不再如此。提示明确队列等待；完成与阻塞以服务端回执为准。

**是否通过层级提高掩盖重叠？** 不是。预演取消 body 传送，采用可用高度约束和面板互斥，内部滚动。

**是否更新了全部建筑模型？** 没有。本轮解决模型可靠加载、恢复、部署路径和展示准确性，没有新造建筑或车辆仿真能力。

**设计审查结论。** 按 Impeccable 保留原有深绿指挥现场，复核桌面和手机截图；此次可交付范围是空间预演、模型恢复与实时对象详情。grill-me 的追问方法用于核对实现和证据，没有把口头自评当作全系统验收。
