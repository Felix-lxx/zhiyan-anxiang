# 导演台浮层堆叠修复

## 已定位原因

- 旧 `styles.css`、`exercise.css`、`training.css` 与导演台样式同时给视角、抽屉和工具栏定位；窄屏下出现顶部与底部定位混用。
- 手机教练面板继承 `overflow: visible`，楼层按钮越过面板底部，实际拦截事件入口点击。
- 教练与其他辅助面板可以同时显示；视角、状态、对象详情未预留各自空间。
- 顶栏实际最小高度与舞台高度计算差 4px，桌面时间轴底部越界。
- 通用请求 busy 状态误触发了与该请求无关的空间预览浮层。

## 修复方式

1. 将沉浸式壳层定位集中到 `frontend/src/director-layout.css`，使用明确作用域，压过旧版本布局规则，不影响地图编辑器与场景预览。
2. 桌面视角、状态、对象导航分区；工具列表与教练面板内部滚动，为底部时间轴保留空间。
3. 事件、更多工具、AI 助手等面板打开时暂时隐藏教练与零散控件；关闭恢复。教练仅隐藏而非销毁，保留输入和人员选择。
4. 手机助手按全屏对话框处理，隐藏背后的顶栏与底栏；其他任务面板与底部入口保持 12px 间隔。
5. 手机恢复居民跟随与对象详情，详情位于底栏上方；视角和教练图标补充可访问名称。
6. 切换辅助工具取消尚未提交的空间预览，避免确认栏留在另一个工具上面；不会撤销已执行的指令。只有空间请求本身等待时才显示空间预览加载状态。

## 验证

- Edge 浏览器，1440×900、1024×768、390×844。
- 普通现场、居民跟随、训练教练、事件列表、AI 助手共 **15 种尺寸／状态组合**。
- 对可见控件矩形检测：无相互覆盖、无超出视口边界、无页面横向溢出。
- 实际点击教练 → 事件 → 更多 → 助手成功；原先手机底栏被楼层按钮拦截的问题不再出现。
- 前端生产构建通过；API 单元测试 4/4。
- 验证使用已有已结束的验收场次，没有改动演练数据，也没有调用外部大模型。

证据：`.tmp/overlap-after.json`；浏览器脚本 `.tmp/inspect-overlap.mjs`；集中检查截图 `.tmp/overlap-after-*.png`。最后一次边界断言仅读取几何位置，没有继续进行视觉微调循环。未宣称已覆盖所有业务页面、所有浏览器缩放比例或真实手机软键盘。

## 自我拷问

- 是把按钮藏起来掩盖问题吗？辅助面板采用互斥呈现，保留明确的打开／关闭入口；手机此前隐藏的视角与详情还补回了。内部内容可滚动，不再溢出遮挡入口。
- 会改变演练状态吗？布局与面板切换不提交业务指令；仅取消未确认的预览，原有执行结果保留。
- 三维画布是否被重建？本轮没有更换场次 key 或卸载三维组件；面板切换不重置现场。
