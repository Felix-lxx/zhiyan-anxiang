# 智演安巷：页面与功能优化分析设计

日期：2026-09-04。审查锚点：frontend/src/components/OperationsCenter.vue，关联登录、首页、社区地图、场景工作台、手机参演和场景 AI 助手。

## 结论

系统已有连续空间、人员排队与会合、集合核验、可编辑分支、任务证据和 AI 解释能力，不能简单称为空壳。主要缺口是配置流程、现场操作和结果解释成熟度不一致。下一轮应先把“场景配置—三维决策—结果观察—核验复盘”做成清楚的完整路径，不继续堆仪表盘，也不更换整套品牌风格。

产品专属性良好：社区、充电棚、楼内剖面、机器人和人员轨迹与消防训练紧密相关。应保留深绿/暖白、三维主画面、显式模型授权和证据关联评分。三维是训练过程的操作载体，不是为了展示模型数量。

## 五项优先问题

### P1：场景操作对象和任务路径断开

事实：SceneWorkspace.vue:13 在没有选中场景时把 activeScene 回退到首项；30–31 行的决策和发布组件在主布局之外；决策返回绑定空函数。上方仍可显示创建表单。两组截图均看到下部通栏表单与上部布局脱节。

设计：固定场景名称、版本、状态和未保存标记；明确选中或创建后才能操作决策/发布；统一放入基本参数、空间预览、决策任务、校验发布四区。未选择不操作首项。返回应真正退出当前编辑并处理未保存内容。

验收：两个不同场景来回切换，参数、预览、决策、发布请求均对应当前 ID；刷新或离开有明确保存/放弃选择。

适用后续工作：Impeccable shape、layout。

### P1：发布失败与成功反馈不可靠

源码证据：ScenePublishPanel.vue:6–9 缺少完整 response.ok 检查与 try/catch/finally，所有 result 使用成功样式。网络或 JSON 异常可能使 busy 不恢复；拒绝发布的信息可能显示成成功。此轮未实际触发故障。

设计：区分字段校验失败、业务拒绝、网络失败、发布成功；错误就近展示、保留输入、可重试；finally 恢复按钮；成功返回当前已发布版本并更新列表和演练入口。

验收：模拟 422、500、断网及超时后均能恢复操作；只有成功响应更新已发布状态。

适用后续工作：Impeccable harden。

### P1：导演台的决定与结果不能稳定同屏理解

事实：training.css 的引导样式隐藏 director-metrics/director-intelligence。导演台同时有镜头、楼层、对象选择、七项工具和指挥表单，打开助手进一步占用画面。手机顶部状态与动作文字缩减，但下方仍有暂停说明，不能说状态完全消失。

设计：保持“到集合点、待核验、未到、风险人数”紧凑状态条；左侧只显示当前步骤；任务、AI、证据使用单一互斥侧栏；镜头是次级工具。引导与自由模式共享状态与动作，只改变渐进展示。

验收：用户可在主视野内确认选中了谁、将执行什么、何时生效、结果在哪里；小屏保留明确模式和暂停/继续标签。

适用后续工作：Impeccable distill、layout、adapt。

### P1：回放、当前状态与规则预测需要严格区分

源码证据：OperationsCenter.vue:207 的抽屉标题可以标为历史时刻，218 行评分却仍来自 current.score/current.score_preview；SpatialTrainingLab.vue 保存预览时刻但未向确认请求提交版本约束。后端下令会重新验证可达性，这是已有保护，不是完全无校验。

设计：每个数据块包含来源和时间；回放评分要么按历史重算，要么标明最终评分而非伪装成历史值。路线预览返回版本、序号、时间，确认发生关键路况变化时展示差异并要求重新预览。

验收：回放 T=0 不出现未标明的未来结果；预览后封路，再确认时明确更新或拒绝，不悄然执行不同的路线。

适用后续工作：Impeccable clarify、harden。

### P2：编辑恢复、地图标签与操作可达性不完整

事实：地图和场景切换会重赋表单，缺少脏数据保护；手机地图多个名称重叠。检测到部分地图/场景按钮约 20px 高；多个 label 未通过 for/id 或嵌套关联输入。这不是所有按钮都不可用，也不是完整无障碍认证结论。

设计：恢复路由中的社区/场景/场次和工作位置；增加未保存提示与草稿恢复；标签按缩放和选择级别显示，重叠时提供对象列表；统一触控区域、字体层级、字段关联和错误说明。

验收：放大、窄屏、键盘访问时仍能选择目标、理解字段和找回工作位置。

适用后续工作：Impeccable adapt、audit、harden。

## 页面设计

| 页面 | 调整方案 | 边界 |
| --- | --- | --- |
| 登录与首页 | 保留现有风格；主操作为继续最近训练/新建训练，常用项目靠前 | 不再堆统计卡片，不优先再做首页大改 |
| 社区地图 | 工具栏、中央地图、选中对象属性区；支持标签避让和重叠对象选择 | 不把所有对象标签永久铺满画布 |
| 场景工作台 | 固定名称/版本上下文，四区切换，统一保存与发布状态 | 不混合创建新场景与编辑默认首场景 |
| 三维导演台 | 三维为主、当前步骤精简、恒定结果条、单一互斥侧栏 | 不让多个大面板同时覆盖现场 |
| 手机参演端 | 我的任务、回执、清点为主，最后同步时间常驻 | 不复制整个电脑导演台 |
| 复盘对比 | 同一时刻/同一居民/不同决策；差异定位人物、路线和事件 | 不只显示两张场景和总分 |

导演台建议结构：

场次/模式/同步时间 —— 暂停或继续/结束
紧凑结果条：到集合点、待核验、未到、风险人数
中央三维：点选人物或道路 → 预览 → 确认 → 观察
一次展开一个任务/AI/证据侧栏
底部：操作结果反馈和事件回放时间轴

常规训练视图应尽量保持三维画面占主要空间；手机采用任务优先布局。此为设计目标，不宣称已经实现。

## 功能深化

### 三维人员与空间解释

已有连续空间、容量排队与护送会合代码及专项测试文件。下一步应把状态解释展示出来：

- 选人显示人数、楼层、位置；预览虚线与已执行实线区别明显。
- 点击排队居民可见受阻路段、前方人数和累计等待。
- 护送明确区分接应中、已会合、共同撤离、集合到达。
- 优先精细化一栋训练楼的门、走廊、楼梯、出口和集合点，邻楼保持简化。
- 不用装饰动画替代服务器实际状态，不把示例户型声称为实测建筑。

### 配置到运行的可追溯联动

当前 spatial_world.py:14 通过道路名称含“南”应用通道状态，exercise_world.py:45 通过任务标题关键词推断任务类型。应改成对象 ID、任务类型枚举、触发事件、目标和角色的明确绑定；改名不得改变行为。

发布校验不能仅检查字段存在：还应检查空间连通、居民起点、有效出口/集合点、目标对象和责任角色。故意的不可达事件允许作为训练设定，但必须显式标记并给出处理途径。

当前示例人口重点人员为固定索引、集中在一栋主楼；后续再增加有明确解释的楼层人口、行动能力、反应延迟等参数，不急于扩大到整座城市。

### AI 专属场景解释

保持刚修复的布局与默认不授权行为。补足选中对象上下文：对“这个居民为何不动”绑定真实居民 ID，而非让用户重复输入名字。回答按结论、数据依据、下一步入口组织；显示快照时间、节选范围与模式。可增加流式显示、复制和错误反馈，但继续不允许模型直接派人、封路或改分。

### 多人协作可靠性

已有 WebSocket 和重连。ParticipantConsole.vue:20 的可操作条件未包含 connected，重连路径还会重新使用旧 drill 对象。需要区分已连接、重连中、快照过期、身份过期；重连先接收新快照再恢复操作，避免旧数据倒退。任务提交要有命令 ID 和重复确认保护，不静默重放过期指令。这些为代码风险，不是本轮已复现的数据损坏。

### 复盘与对比

已有实际可编辑分支和同人同刻比较，同时也保留预设策略预测。应显式分为“我的历史分支”与“规则预测”，不能混称已发生结果。

实际分支比较支持同步时间、联动镜头/人物选择、差异路线和关键事件定位。报告需要结论、证据、解释和下一轮目标；现有 JSON 导出保留，并增加可读 HTML/打印版。

## 统一视觉规则

- 管理编辑页暖白，演练现场深绿；维持现有 SVG 图标体系。
- 同类表单、按钮、抽屉、通知使用一致尺寸和状态；正文不靠缩小解决空间问题。
- 信息用分组、折叠与按需展示精简，不再增加无意义卡片。
- 地图标签按重要性和缩放显示；颜色之外有文字/形状。
- 动效表达选中、改道、会合和完成，火烟效果不遮挡关键人物。
- 局部样式应逐步收敛为共享控件与设计变量，避免每轮追加相互覆盖的 CSS。

## 用户视角与情绪路径

- 新手设计员：最危险的是不清楚正在创建还是编辑谁，发布在哪里、是否成功。
- 熟练总控：需要快速定位风险与操作结果，不应反复开关不同面板找状态。
- 键盘/辅助技术用户：表单有可见文字不等于标签已绑定；返回动作必须真实有效。
- 入口与三维场景构成体验高点；场景长页、失败无恢复构成低谷；用证据清楚的复盘结束训练，避免只有分数。

认知负担：场景页与导演台均至少存在单一焦点、层级、一次一个决定和渐进展示方面的问题。不是机械地禁止超过四个按钮，而是让同一决策只暴露必要选项。

次要观察：charging_shed 改为充电棚；A* 路线面向普通用户可显示规划路线；重复继续按钮收敛为一个主要动作；手机触控区与次要文字统一优化。

## 开发顺序与验收

| 批次 | 交付 | 验收 |
| --- | --- | --- |
| 1 | 场景选择、编辑、校验、发布闭环 | 两场景不串数据，失败可恢复，成功状态一致 |
| 2 | 导演台重排、地图标签与行为反馈 | 同屏看懂选中对象、下达动作和实际结果 |
| 3 | 预览版本、断线恢复、任务幂等 | 路况变化要求更新预览；重连不倒退、不重复记账 |
| 4 | AI 对象解释、同人同刻对比、可读报告 | 能解释同一居民在两次决策后的差异与依据 |

每批交付前先做功能状态与可访问性验证，再做 Impeccable polish；不以新增按钮数量验收。

建议主验收流程：选择居民 → 比较两条路线 → 下令 → 观察队列与会合 → 集合核验 → 从决策前重做 → 比较同一居民的结果。

## 正式部署前的独立门槛

当前 auth.py 仍为开发环境引导账号；仿真调度为单进程本地机制。正式账户权限、备份恢复、并发隔离、容量与真实用户验证需单独完成。当前竞赛 Beta 不能直接声称是生产系统或真实火场指挥系统。

## 待确定的取舍

1. 下一轮先完善场景配置发布闭环，还是先重构三维导演台？证据支持先前者，避免后续训练建在不清楚的场景状态上。
2. 当前优先交付竞赛演示版，还是面向社区多用户试用？前者聚焦一条可靠训练闭环；后者需同步投入账户、断线、审计和部署保障。
