# 训练任务与统一工作区升级

本轮落地改造计划的第一批：当前任务、训练简报、首页恢复与导演台工作区。厨房和充电棚继续使用已有仿真、命令、任务证据及评分规则。本轮没有修改物理模型参数或通过调整评分掩盖执行问题。

## 用户现在如何完成训练

1. 首页选择恢复未完成训练，或准备新训练。恢复入口会读取具体场次的当前阶段、到场与清点人数、未核验任务数。
2. 新建场次首先显示训练简报：案例、模式、火点、人数、重点人员、岗位、设备、责任任务与结束条件。创建时冻结目标和初始条件。
3. 开始训练后，同一面板显示服务端生成的当前任务，最多突出三项行动。确认报警会记录应急指挥人员的响应事件。
4. “安排分流与重点护送”直接进入助手的目标计划；任务建议定位具体任务，失联或受阻提示定位具体居民，清点建议进入到场名单。
5. 任务、助手、室内观察和清点在一个工作区内切换；返回当前任务后继续查看进展。任务输入在工作区切换期间保留，刷新页面则重新读取服务端任务状态，未提交文字不宣称已保存。
6. 开始核验前检查实际前置条件。居民到场不等于清点，机器人到场不等于广播完成，处置计时结束不等于证据已提交。
7. 结束确认列明未到场、未清点、未护送、未核验和未结束指令等事项，允许组织者按实际结果结束训练，不替用户填补完成记录。

## 状态与代码边界

| 层 | 文件 | 责任 |
| --- | --- | --- |
| 冻结输入 | `backend/app/services/exercise_world.py` | 在新场次世界中写入 `training_briefing` |
| 只读业务投影 | `backend/app/services/training_journey.py` | 从人员、任务、指令、机器人和完整事件计算当前阶段及建议，不推进时钟、不发命令 |
| API 与实时 | `backend/app/api/routes/operations.py` | 快照包含 `journey`，通过既有 WebSocket 差量同步；单场 `/journey` 接口保留归属鉴权 |
| 首页历史 | `backend/app/services/drill_history.py` | 返回最近 ready/running/paused 场次和最近结束场次，避免逐条历史运行仿真 |
| 前端契约 | `frontend/src/domain/training.ts` | 明确阶段、动作类型、目标 ID、资源、结束条件 |
| 首页入口 | `frontend/src/components/TrainingHomeActions.vue` | 最多读取一场当前进度；取消过时请求，失败可重试或直接恢复场次 |
| 工作区正文 | `frontend/src/components/TrainingJourneyPanel.vue` | 展示简报、当前事项、等待条件与完成条件，不重复推断阶段 |
| 页面协调 | `frontend/src/components/OperationsCenter.vue` | 动作映射到已有命令/定位/任务/助手；互斥工作区导航 |

`journey` 是可重建投影，不另存一张容易失配的进度表。静态简报随创建事件冻结；动态阶段在同一权威状态上重新计算。刷新后重建；已结束场次保留原评分，只生成只读结果引导。旧场次使用 `legacy_derived` 明确标识的兼容简报，不改写历史事件。

首页只对一个待继续场次请求进度。历史页仍执行服务端分页，不对全部场次复制人员图或计算仿真。新字段随现有 JSON 世界/快照传输，无数据库迁移；旧前端忽略新增字段，新前端对旧快照保留原引导工具。

发布前修正首页恢复优先级：先选择最近的进行中或暂停训练，只有没有这类训练时才选择待启动场次，避免新建简报覆盖尚未完成的现场。

## 布局与交互约束

- 复用既有浅色首页、深色导演台及设计令牌。
- 宽屏工作区占实际右侧宽度，三维画布相应缩窄。
- 1100px 以下复用顶栏下方的单个工作区，正文内部滚动，顶部场次控制保留。
- 面板切换保留任务证据输入；开始、暂停、继续和结束仍使用统一命令链。
- 当前事项正文 16px、辅助信息 14px，动作按钮至少 44px。
- 助手新增返回当前任务时同步调整 Grid 行，避免将返回按钮挤入对话滚动区。

## 自我审查

**会不会只是又加一块看板？** 每个建议携带动作类型与具体目标 ID，导航到已存在的任务执行、三维定位、智能体计划或清点操作。服务端没有因“查看建议”而更改结果。

**会不会把等待误写成完成？** 结束条件分别检查实际到达、清点、护送、责任任务、指令与响应事件。机器人等待保持任务队列状态，暂停时明确说明不推进。

**是否改写旧场次或制造高分？** 没有修改评分公式、任务时限或历史事件。新简报只随新世界冻结；旧世界只做兼容读取。

**未完成输入是否真的保存？** 面板切换用既有 KeepAlive 保留输入；服务端保存发生在提交核验证据后。刷新前未提交的文字仍属本地草稿，不作持久化承诺。
