# 室内门控、智能体监督与工作区完善

## 本轮审查范围

沿实际执行链阅读了厨房冻结布局、分区烟气、居民与护送员运动、门控命令、智能体监督投影、实时补丁、三维室内模型、任务抽屉和助手导航。保留工作区原有未提交改动。本次不改变评分权重，也不删除历史场次。

## 已修复的问题

| 问题 | 实现 | 可观察结果 |
| --- | --- | --- |
| 人工关门与智能体判断房内是否有人使用两套规则 | `indoor_safety.py` 统一居民节点、当前通道与护送员实际位置判定；命令、智能体和界面投影共同调用 | 房内或门口有人时，界面提前显示具体人员，服务端仍在提交时重新校验 |
| 同一状态重复操作产生无效门状态事件 | 房门目标状态等于当前状态时返回权威快照 | 使用不同命令 ID 再次打开已打开的门，不会重复生成门状态变化事件 |
| 三维点门只能进入笼统楼内页面 | 模型携带 `doorId`，通过导演台切换到对应楼层和房门 | 选中门排到本层列表第一项，显示选中状态；暂停时也能查看但不能操作 |
| 目标居民被门困住，助手仍优先提示一般责任任务 | 监督投影检查关闭门与受阻居民的关联，输出明确门 ID；前端复用原抽屉导航 | 点击“检查受阻房门”返回该门；助手不会自行开门 |
| 人员危险提示被一般核验任务压后 | 执行中或等待中的计划优先定位受阻居民 | 尚有受阻人员时，下一步首先指向受阻原因；人工审批与复核阶段仍保留原优先级 |
| 开启门扇伸向公共走廊 | 门框沿冻结通道法向定位，开启门扇向房间侧停靠，门扇和把手位于通行净宽之外 | 开门后的静态形体不占用该门口的通行净宽；关闭模型与服务器状态一致 |
| 短屏抽屉大部分高度被上下控件占据 | 桌面为三维现场预留独立右栏；中小屏将任务作为当前工作区，隐藏背景工具 | 关键操作不再夹在视角条与时间轴之间，关闭后恢复现场工具 |
| 操作面板阅读顺序过长 | 删除重复标题和长说明，房门操作优先，烟气分区折叠 | 正文保持16px，辅助14px，操作目标至少44px |

门口颜色来自权威状态：关闭为橙红，打开但仍有占用为黄色，打开且无占用为绿色。界面始终同时显示文字，颜色不作为唯一判断依据。

## 执行与数据一致性

1. 仿真生成当前人员与护送员位置。
2. 统一门控策略生成 `occupants`、`can_close`、`blocked_reason`。
3. 页面展示原因，智能体监督读取同一批人员的受阻事实。
4. 操作者确认后，命令应用服务重新校验当前状态。
5. 成功事件改变门状态；烟气、路径、模型和复盘读取该事件。

新增占用投影复制室内状态的门列表，不把动态人员写入烟气时间线缓存，避免后一个时刻污染前一个时刻的回放。所有字段均为投影字段，无数据库迁移。

- 后端16项定向检查通过，覆盖厨房冻结、门控、连续移动、清点、护送占用、智能体监督与同状态重复操作。
- 三维15项检查通过，包含门框方向、开启门扇与把手净宽、楼梯开洞、实例化、路径转角与历史高度。

- 浏览器在1440×900、1366×650、390×844检查厨房准备与门控。页面检查使用隔离布局数据；业务动作规则由前述后端检查验证。没有据此声称本轮重新取得完整演练满分。
- 桌面抽屉与画布采用不同区域；手机抽屉内部滚动。未发现本次检查区域的横向溢出。

## 仍需升级的实际缺口

1. **设备操作尚未全部实体化。** `indoor_commands.py` 仍为导演即时门控；`fire_environment.py` 的燃气影响读取 `task.completed`。责任人接单、到位、核验已有流程，但还不是一名实体操作员走到阀门后持续作业的完整模型。后续应拆分动作完成事件与人工证据核验，再连接到环境变化。
2. **灶台、人员节点与火源锚点尚未完全分离。** 火源和任务位置仍主要取房间通行节点，厨房资产是避让通道的视觉模型。下一阶段应冻结设备 ID、操作接近点和灶台表面火源位置，统一预览、运行和复盘，不能只在前端移动火焰。
3. **门扇扫掠尚未模拟。** 本轮保证的是开启后的门扇及把手不占用通行净宽，没有加入开合过程扫掠体碰撞、门口操作员到位或开启时长；不能由此宣称全部模型零穿插。
4. **重连仍可能位置校正。** `actorMotion.ts` 在长间隔或无法拼接已确认路径时直接对齐服务器坐标，避免画出穿墙捷径。若要进一步平滑，需要服务端提供有界已走路径片段，不能用直线补间掩盖缺失路径。
5. **大人口同步仍有可压缩空间。** 实体增量覆盖居民、护送员与车辆，门占用列表仍随环境分支发送；大量室内门时应先测量负载，再增加门实体增量或摘要，而非现在直接扩大数据。

## 自我拷问结论

- 页面禁用是否代替了后端安全判断？没有，服务端仍重新核对本次快照。
- 智能体建议是否与人工操作使用相同依据？门占用已统一；更广泛的设备操作仍按上述缺口继续推进。
- 视觉颜色是否冒充执行完成？没有，门模型只反映已确认状态。
- 全屏抽屉是否覆盖了主要控制？位于顶栏下；桌面独立右栏，手机仅隐藏背景现场工具。
- 是否通过重新建场或改分数解决问题？没有，本轮未改历史记录和评分口径。

下一阶段优先完成“厨房设备锚点—执行人接近—动作完成—环境变化—人工核验”的链路，沿用本轮门控定位与统一工作区。
