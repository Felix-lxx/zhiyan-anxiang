# ADR-0001：以模块化单体承载实时演练

- 状态：接受
- 日期：2026-10-20
- 决策者：智演安巷项目组

## 背景

一次消防演练指令会同时改变道路状态、人员路径、通道容量、机器人或车辆任务、环境风险、评分与复盘证据。它们需要在同一版本下提交并实时展示。若在当前阶段拆成多个网络服务，需要额外解决跨服务事务、版本竞争、回放一致性和本地部署复杂度。

## 决策

保持一个 FastAPI 部署单元和一个权威数据库，按 API、领域服务、模型与契约分层。后台演练推进与智能体监督作为受生命周期托管的进程任务运行，并用数据库租约避免重复推进。

## 后果

### 正面

- 命令、事件、快照和评分证据可在同一事务内提交。
- 导演台、手机端和 Three.js 能通过递增状态版本观察一致结果。
- 本地竞赛演示只需启动前端、后端和数据库，不引入消息中间件或服务编排负担。

### 约束

- 大人口与长场次必须采用增量计算、检查点和实体补丁，而不是依赖横向拆服务解决性能。
- 领域服务不能反向耦合路由。当前历史适配路径必须逐步抽取为应用服务。
- 未来如需要多 worker，先把调度、幂等键、事务性事件投递与容量指标验收完整，再拆分进程。

## 不采用的方案

- **立即微服务化**：增加跨服务一致性风险，不适合当前单场次演练规模。
- **浏览器作为仿真权威**：断线、多导演并发和刷新后无法证明结果可信。
- **仅用定时轮询同步完整快照**：会在大人口模型下放大网络和渲染压力。
