# 训练信息回收与经验审核闭环

本轮处理“训练结束后信息是否保留、在哪里查看、下一次如何使用”。继续复用权威场次、评分、事件流、知识版本与人工审核，不增加新的角色或独立聊天窗口。

## 交付行为

| 环节 | 当前行为 | 数据依据 |
| --- | --- | --- |
| 结束训练 | 同一事务冻结成绩、生成档案和经验草稿；归档失败时结束操作回滚 | 场次结束命令、评分与档案唯一约束 |
| 原始档案 | 保存人员、任务、剩余火情、设备状态、事件序号范围和内容校验值 | `drill_archives.payload`，新建档案格式版本 2 |
| 失败或手动训练 | 同样记录未到、未清点、暴露与未核验任务 | 结束时真实状态，不要求先有智能体计划 |
| 历史训练 | GET 只读；组织者点击补建，保留原始成绩 | 标记 `historical_reconstruction`，原运行模型修订记为未知 |
| 经验候选 | 生成草稿，不自动发布；原始事实与可修订正文分开保存 | 既有 KnowledgeDocument / KnowledgeVersion 与档案来源关联 |
| 后续检索 | 仅检索已发布、未过期且有权限的资料 | 沿用社区、所有者、案例筛选与版本引用 |
| 经验适用性 | 单场档案即使条件一致，也不直接推断策略收益 | `simulation_archive` 与预测—观察对照来源分别识别 |
| 助手问答 | 按场次与账号保存问题、回复、引用与观察时刻，分页恢复 | conversation + exchange，默认每页 20 轮，接口上限 50 轮 |
| 清空问答 | 删除当前账号本场对话，提升代次，拒绝清空前的迟到回复 | generation 校验、短事务行锁、请求唯一约束 |

每份档案保存全体人员的结束位置、状态、护送与清点、暴露值及首次超阈值时刻（有记录时）；责任任务保存真实核验和证据字段。原始事件继续由既有事件流保管，档案包含最多 24 条关键事件摘要及完整事件序号范围。归档不等于录制视频或每帧三维画面。

已删除的未发布经验草稿不会因重复读取或补建档案而重新出现；训练档案仍保留。已发布资料继续使用原有停用与版本审计机制。助手清空不改写评分、事件或经验正文，档案中的“结束时问答轮数”保留当时观察值。

## 页面与使用路径

结束训练后自动进入复盘，右侧评分区顶部展示“训练档案”，可下载 JSON，或直接进入知识工作区完善、提交审核和发布经验。历史场次显示“补建本场训练档案”。新训练原始事实无预测列、无虚构批准版本；原有智能体对照经验继续显示其真实预测与观察。

助手使用原来的场景对话区，增加保存状态、重新读取和更早对话入口。读取失败时保留错误提示，暂不允许用未知对话代次发送；失败重试复用请求编号，避免重复写入。恢复对话不会恢复外部模型授权。

短屏打开助手时，复盘证据不再被第二行挤到只剩标题；主区滚动显示场景、档案与证据，时间线保留。新增档案正文 16px、辅助信息 14px、主要按钮至少 44px。

## 代码边界

| 文件 | 职责 |
| --- | --- |
| `backend/app/models/training.py` | 档案、对话头与问答存储，唯一约束和分页索引 |
| `backend/app/services/training_archive.py` | 冻结结束事实、经验草稿与统一经验来源适配 |
| `backend/app/services/assistant_conversations.py` | 分页、幂等、代次校验、清空与迟到回复保护 |
| `backend/app/api/routes/training.py` | 有权限的档案读取与历史补建 |
| `backend/app/api/routes/assistant.py` | 问答生成接入存储与每账号 30 次/分钟的未缓存请求限制 |
| `backend/app/api/routes/operations.py` | 结束事务接入自动归档 |
| `backend/app/services/knowledge.py` / `knowledge_applicability.py` | 两类经验来源、发布检索与适用性判断 |
| `frontend/src/components/TrainingArchivePanel.vue` | 档案读取、补建、下载和经验跳转 |
| `SceneAssistant.vue` / `KnowledgeObservation.vue` / `ReplayWorkspace.vue` | 留存交互、事实呈现和复盘工作区 |

接口均位于现有 `/api/v1` 下：

- `GET /drills/{id}/archive`：只读，没有档案时返回 `archive: null`。
- `POST /drills/{id}/archive`：显式补建已结束训练，重复请求返回原档案。
- `GET /drills/{id}/assistant/conversation?limit=20&before={sequence}`：有界分页。
- `DELETE /drills/{id}/assistant/conversation?generation={n}`：只清空当前账号本场对话。
- `POST /drills/{id}/assistant/chat`：增加可选 `request_id`、`conversation_generation`，旧客户端仍可调用。

对话持久化与清空只锁定短数据库事务，不在调用模型时持有行锁。过期代次、编号与问题内容冲突返回 409；越权请求沿用场次归属检查。

## 启动与数据升级

重启后端，通过项目现有 `initialize_schema()` 创建 `drill_archives`、`assistant_conversations`、`assistant_exchanges` 三张新表，不改写既有评分、事件或场景。部署前按现有备份流程备份数据库，生产数据库账号需要该项目现有初始化流程所要求的 DDL 权限。

没有后台批量重建历史档案，也没有自动将草稿发布到 RAG。现场事实、模拟结果与专业知识继续分别保存。未做自动训练模型、策略参数自学习或录像存储。

执行：

```powershell
Set-Location backend
.venv\Scripts\python.exe -m pytest tests/test_training_collection.py tests/test_scene_assistant.py tests/test_knowledge_experience.py tests/test_knowledge_applicability.py tests/test_score_evidence.py -q -p no:cacheprovider

Set-Location ..\frontend
npm run build
```

真实浏览器操作了已有厨房历史场次：补建档案后原始 30 分保留，点击经验入口可打开真实草稿；问答发送后刷新恢复为一问一答，清空后重新读取为空。检查了 1440×900、390×844 和 1366×650 的代表性布局，新增档案区域在桌面/手机宽度下无横向溢出，正文计算字号 16px。完整项目评分流程、大人口容量、外部模型/语音服务调用及 PostgreSQL 多进程并发本轮未执行。
