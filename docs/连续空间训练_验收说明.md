# 连续空间训练 V3：使用与验收

## 入口与数据安全

本轮启用新的冻结世界 `schema_version=3`。已有 V1/V2 场次继续原规则，不能把旧楼层示意回放冒充新模型。刷新演练中心，在旧场次左栏点击「新建连续空间训练」，或在已结束场次点击「新开一轮」。不会清空已有记录。

没有提供实测户型，因此采用标注清楚的示例空间。当前是“一栋楼、两个出口方向、独立集合位置”的软件训练，不是消防疏散安全计算工具。

## 六项实际行为

| 项目 | 如何操作 | 验收依据 |
| --- | --- | --- |
| 统一配置与运行 | 修改人口、水源、南通道、楼梯宽度，保存预览，再新建演练 | 预览与场次调用同一个冻结世界与仿真入口；老场次保持旧参数 |
| 连续空间 | 跟随一个楼内居民，预览后下令撤离 | 服务端连续 x/y/height，房门、走廊、楼梯、楼门、室外、出口、集合位置逐段到达 |
| 容量与会合 | 窄／宽楼梯比较；为重点居民安排护送 | 每条通道按宽度分配车道，同车道保持 0.8 训练单位间隔；实际会合后才 assisted；累计排队不清零 |
| 空间操作 | 楼层按钮、逐人选择、三维框选，点击出口或路线按钮 | 预览不会写入指令；确认才改变目标；服务器会重新检查可达性 |
| 集合核验与搜索 | 打开清点，尝试核验未到者；为未到者指定责任人 | 未到集合点返回 409；已到逐人核验留证；搜索员沿通道会合后恢复撤离 |
| 历史重做 | 选择决定前创建分支，继续训练并改走另一出口 | 精确到事件序号，保留同秒更早决定，丢弃该决定及未来；同批居民、同一已发生时刻双视图逐人比较 |

## 自我拷问与修正

1. **只是换了文字和按钮吗？** 不：新纯函数仿真生成连续三维位置；预览、实时、回放、历史分支共享同一入口，前端不再给 V3 居民虚构楼层坐标。
2. **仍能从未到达直接点成到场吗？** 不能。导演和手机共用服务端到场校验；搜索和清点是两个不同动作。到场与核验分开，评分同时读取这两项。
3. **有队列是否就能完整撤离？** 不能这样判断。开发中增加交汇节点刚性互锁后，60 人主案例只到达 10／20 人；这套互锁规则已撤回。最终保留通过完整回归的分车道间距与简化节点合流，不能称为全局无碰撞人群仿真。
4. **历史分支会带入原场次未来或复用手机凭证吗？** 不会。复制截止点前事件，重映射机器人目标事件 ID，剔除身份凭证；未完成责任任务由分支总控代办，原证据保留来源说明。
5. **重新选择之后只是预测按钮吗？** 不是。会生成真正独立的暂停场次，可继续、封路、下令、清点和结束；实际对比不读取任何一侧尚未发生的未来。
6. **为什么用户过去找不到功能？** 旧场次保持旧模型。现在增加显式新建入口，并把核心操作集中为「指挥／清点／重做」，不继续叠加仪表盘指标卡。

## 已执行验证

- 后端完整回归：37 passed（130.15 秒），包含原功能和 8 个新增连续训练测试；60 人完整案例完成疏散和重点护送。
- 前端 TypeScript 与生产构建通过，三维包仍有约 738 kB 的体积告警。
- Edge 实际操作：选楼层、无写入预览、确认撤离、真实鼠标框选、创建决定前分支、在分支改派南侧、双三维实际结果对比、独立手机登记、未到者不可清点；无页面脚本异常。
- 桌面 1440×900 与手机 390×844 检查，未发现横向页面溢出。Impeccable 检查后修正标签对比度、建筑标签遮挡和框选入口，并让确认区进入可见滚动范围。
- 仅使用隔离数据库 `tmp/spatial-training-qa.db` 和 8001/5174 验证，没有清空用户原演练库。
- 自动化脚本：`backend/tests/test_spatial_training.py`、`tmp/verify_spatial_training.cjs`。截图：`tmp/spatial-route-preview.png`、`tmp/spatial-editable-branch.png`、`tmp/spatial-phone-registration.png`。

## 明确边界

示例房间和集合位置、通道间距、速度、烟气增长均为训练规则，未实测标定；路口允许简化合流，尚非全局连续避碰。分支对照是读取两场的同一时刻，不是预测原训练尚未发生的未来。真实机器人、消防设备、定位感知和 CFD 未接入。单进程本地运行已验证，多机多人压力测试与生产安全审计未完成。
